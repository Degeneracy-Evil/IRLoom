# M7 审查与研究重定位：从局部参数选择到跨算子接口决策

**研究备忘录 · 2026-10-19。** 依据 `experiments/reports/m7-interpretation.md`、`m7-findings.md` 及 `irloom/m7.py`、`irloom/context.py` 的提交内容进行审查，未在原实验主机重新运行。

## 1. M7 的有效证据和未达成的假设

M7 两轮各 36/36 正确，共 1,080 个计时批次。513×513 上，当高层选择 fused 时，tile32 相对于 none 在单消费者上下文约为 0.893×，在 row_reduce 上约为 1.053–1.058×，重复呈现方向变化。相同规模的最优全程序路径分别是 fused-none 与 fused-tile32。

然而，这次 `affine-loop-tile` 对**整张图**的循环生效，并非仅操作目标 D=A*B。方向反转出现在融合后的路径，此时局部 affine 循环体已因上下文不同而改变；局部严格匹配的 separate 路径没有出现最优动作反转。结论限于**完整程序路径存在上下文相关性**，还不能声称“局部 IR 相同、外部上下文迫使其最佳局部动作改变”。

上游历史（L2）在此数据中对选路无增量：48 个相应决策的 L1/L2 相同。对 fused 的新规模留出，L0/L1/L2 的两轮 regret 约为 1.161/1.104/1.104，固定 none 则仅 1.009 左右。六个完整 case、两批同机测量不支持训练通用神经架构。这里应**终止继续按旧动作扩 Shape 或训练 Attention**，而不是设法达到人为样本量门槛。

## 2. 为什么原实验难以产生强烈的“上下文必要性”

如果一次局部优化 `a` 只改变生产者 `R` 的执行，保持其输出值、数据布局、物化方式以及消费者接口不变，而且消费者仍独立执行，那么整图代价经常近似：

```text
T(a, G, H) ≈ T_producer(a, H) + T_consumers(G, H)
```

此时第二项几乎与 `a` 无关，局部最佳动作自然不太依赖外部消费者。缓存驻留与代码布局可能打破加性，但通常不是最适合立项的主要耦合机制。

**真正值得验证的跨层级耦合，发生在一次决策同时改变生产者及消费者的接口或共享资源时**，例如中间张量布局、pack/unpack 与转置成本、融合与物化、重复计算与共享中间值、Buffer lifetime、片上存储占用等。此时局部计算代价下降未必令整图更快；不同消费者甚至可能偏好相反的表示或布局。

还有一个理论边界：若当前 IR、编译器全部相关状态与硬件/输入分布已完全给定，则完整的未来合法变换集合及机器代码代价原则上不依赖达到当前 IR 的历史。历史的合理价值应被定位为**有限预算下的计算摘要、仍可访问的高层抽象、已试分支及真实硬件反馈**，而非必然具有当前完整 IR 所没有的“真实程序语义信息”。

因此，持续状态与跨层 Attention 应被视为可能使优化器更高效的**实现机制**，而不是当前必须证明其存在的研究目标。

## 3. 新的核心研究命题

> 能否在 MLIR 的高层计算语义、跨算子数据流和低层目标硬件实现之间，联合选择中间数据布局、融合/物化及执行调度，并在固定优化预算下，比传统逐阶段局部决策产生更快的最终程序？

这仍然是以**更高的编译产物性能**为目标的通用编译器研究，而不是仅对单算子选 tile 参数，也不绑定 NVIDIA。需要严格对照已有布局传播、Tensor 编译自动调优、跨层级搜索和编译器超优化工作，不能把“联合优化”或“硬件感知”本身当作论文贡献。

MLIR 当前文档已有 `transform.structured.pack`、`pack_transpose`、`lower_pack`、`linalg` 布局传播等组件，可作为技术调查入口；**是否存在于项目当前 LLVM/MLIR 18.1.3 工具及其具体语法，须通过本机 help、release/18.x 文档和实际编译验证，不能直接照抄最新文档。**

- MLIR Transform Dialect：https://mlir.llvm.org/docs/Dialects/Transform/
- MLIR Linalg Dialect：https://mlir.llvm.org/docs/Dialects/Linalg/
- MLIR Tensor Dialect：https://mlir.llvm.org/docs/Dialects/TensorOps/

## 4. 下一项实验：只做一个有明确停机条件的耦合验证

**M8.0 — 合法性审计。** 先选一个两消费者的简短 DAG，例如同一中间张量既被行方向消费、又被转置/列方向消费。优先使用 MLIR 官方已有变换表达以下至少两个合法实现：保留原数据布局、改变中间布局且相应修改消费者；或保留物化、对受支持的生产者—消费者进行融合/重计算。生成候选时统一语义与 ABI。逐路径收集真实高层 IR、Lowering、内存转换/临时分配数量及目标代码。如果 MLIR 18 无法合法完整 Lowering，可做最小范围的可审阅变换适配，但不要为一个 feasibility 实验新建大型 Pass 系统。

**M8.1 — 强耦合受控对照。** 固定同一原始 producer 的计算、Shape、dtype，构造两种确有不同消费偏好的上下文，冻结合法候选，再进行正确性与重复原生计时。**所有 pack/unpack、transpose、copy、alloc/dealloc 均计入完整程序时间**。报告各上下文的局部最优 vs 全图最优、跨上下文改变决策的效果、强静态规则及完整当前 IR 可否识别正确选路。

**停机条件：** 若实际编译链无法可靠表达这些合法替代路径，或同一便宜规则已在两个上下文都接近最优、没有清晰超过噪声的跨图规划损失，就停止在此场景继续投入，不启动自动数据扩张、神经训练或硬件迁移。负结果可以用于重新决定研究切入点。

## 5. 如果耦合效应成立，才进行最小架构实验

先明确必要的成本和信息基线：当前完整 IR + 简单解析特征 + 目标硬件信息，对比当前 IR + 高层算子语义/关系锚点 + 下游代价预测。再研究是否值得使用结构化图 Attention 在高层生产者、消费者和目标硬件资源之间交换信息。持续记忆可以保存已试优化路径与实测反馈，但必须和完整历史重新编码、普通图消息传递/池化以及参数量/输入相同的小模型比较。

核心指标是**相同真实编译/测量预算下最优代码延迟、wall-clock 优化总成本、泛化到未见程序图及机器时的效果**。必要时先用另一种 CPU/ARM/Ascend 做不同硬件对照，避免固定 CPU 性能特征被误认为通用推理。

## 6. 给本地 Agent 的边界

下一次开发**只允许先做 M8.0 合法性与最小端到端证明**，验证可用的跨生产者—消费者接口决策，不需要立刻实现完整 2×N Benchmark，也不需要训练任何模型。形成简短 feasibility 记录与可复现命令后，再决定是否进入 M8.1。旧 M0–M7 数据和报告原样保留，遵守目前不计算 hash、不新增单元测试的用户约定；全部候选继续保持独立数值正确性校验。

如果上述可行性失败，应带着明确技术原因停止新实验并回到研究定位讨论，**不要自动改成新一轮局部 tiling、Shape 扫描或另一个弱信息对照**。
