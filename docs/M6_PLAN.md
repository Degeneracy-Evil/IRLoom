# M5 审查与 M6：迈向可学习的跨阶段性能决策

**状态：2026-10-19 研究计划。** 已检查 `m5-interpretation.md`、`m5-findings.md`、`m5-results.json`、`M5_PROTOCOL.md` 和 `irloom/decision.py`。本文中的附加组合分析来自已提交完整候选数据；没有在原主机重新编译或运行新基准。

## 1. M5 已经证明的事实

M5 在新增六个 matmul Shape 和四个 row reduction Shape 上完成 2×3 因子实验；两轮各 60/60 候选正确，共 1,800 个批量计时样本。三个 matmul Shape 的四候选前瞻分配优于阶段贪心，改善分别约为 4.74×、1.14×、1.09×；归约上的简单规则已经接近最佳。两个程序家族和十个静态 Shape 不足以支持程序泛化结论。

代码审查揭示一个**影响研究定位的关键区别**：当前 `lookahead` 的查询动作固定为高层两个分支分别测试 `none` 与 `tile16`，只在最后选择实测最优。它是**均衡的固定探针分配 / fixed balanced coverage**，并不依据反馈自适应决定下一次查询，也没有学到下游性能价值函数。名称可以保留以兼容旧实验，但未来报告必须明确这一点，不能称作已有学习型前瞻优化器。

进一步对每个程序家族的完整六候选池穷举 15 种四候选固定子集：

- 新增 matmul 六个 Shape：两轮各有 **3/15** 种固定子集能够在所有六个 Shape 上覆盖全池最优；M5 当前策略只是其中之一。
- row reduction 四个 Shape：两轮各有 **1/15** 种固定子集能全部达到 oracle；但简单静态/贪心分配通常也足够接近最优。
- 若将同一个固定四候选子集应用于整个 matmul 集合，15 种子集的“逐实例 regret 几何均值”的算术平均约为 **1.203× / 1.204×**（两轮）。这只是穷举后的离线描述性随机子集参考，不是随机在线运行性能，也不是泛化保证。

因此，当前结果主要支持**选择更有价值的候选覆盖**。它还没有证明“长期保留历史 IR 信息”“Cross-Level Attention”或“对未来优化潜力的预测”有额外价值。四候选实际编译/执行调用次数已对齐，但实际执行墙钟不等，不得把固定调用预算声称为等时间预算。

## 2. 下一阶段的研究问题

现在不再反复验证一个固定 `tile16` 探针为何成功，而是问：

> **当下游可选优化动作更丰富、少量固定探针无法稳稳覆盖 oracle 时，能否用程序结构、目标机器信息和少量已执行探针，预测下一步最值得编译/运行的候选，并在相同成本下生成更快的代码？**

更形式化地，若高层状态为 `s`、高层动作 `a`、后续合法动作集合 `B(s,a)`、机器 `H`，可以把未来最优代价作为学习目标：

`V(s,a,H) = min_{b in B(s,a)} T(Codegen(b(a(s))),H)`

这不要求枚举整个真实编译空间，也不意味着该函数天然可微。模型需要预测未测路径的相对潜力，而不只是记住当前候选的测量标签。

研究的两条贡献主线保持不变：
1. **编译决策：** 真实跨阶段协同、有限预算决策、允许使用实测反馈回溯与重新分配探针；
2. **架构方法：** 在有证据支撑时测试跨层级 IR 的结构化表示、持续状态、硬件条件化信息交互，最终改善生成代码性能。

MLIR 执行合法变换和 Lowering；学习模型仅参与决策。研究方法不绑定 NVIDIA、固定 Attention 比例或单一 ISA。

## 3. M6-A — 扩展候选空间并建立强无学习基线

优先复用 M5 的正确性/测量闭环。对至少一个已知存在路径交互的程序，尝试更丰富的合法低层动作（例如 `none`、`tile4`、`tile8`、`tile16`、`tile32`、`unroll4`）；实际动作以当前 MLIR 18 工具链支持和语义正确为准。建议初步形成 2×5 或 2×6 的候选池，保留全部编译、正确性、原始延迟及目标代码去重信息。**先冻结候选空间、参数边界和 Shape 采样方式，再运行正式数据**；不要根据测试结果删掉不利动作。

增加与 matmul、row reduction 有**真正不同计算结构**的程序模板，例如带逐元素后处理的计算链或可融合程序；每个模板如果要进入 A×B 实验，必须有实际可执行且语义合法的高、低层决策点。保持开发开销可控，优先一到两个新模板而不是一次造完整 Benchmark Suite。增加独立输入实例（Shape / layout / 计算规模），其中需要有预先冻结的盲测实例；两次计时只能提高标签可靠性，不能充当独立训练样本。

先离线评价以下强基线：

- **固定覆盖：** 预先选定并与 M5 对照的几种跨分支候选子集；
- **随机/分层随机：** 在相同 `k` 次编译测量预算下，从合法池选择 `k` 个唯一候选；多随机种子，明确给出均值与分布；
- **阶段贪心：** 先比较两条高层的默认后端结果，再局部搜索；
- **受控自适应探针：** 利用已测候选来决定后续的查询分配，而不是全部在查询前固定；
- **全池 oracle：** 只做事后上下界，不参与策略决策。

报告 `k=2,4,6` 等预算点的 best-found 延迟、regret、查询次数和编译/测量总墙钟；若某些程序缺合法路径，要显式处理。前期可使用完整池做**离线回放**，不把它宣传成真正在线优化。尤其要检验 M5 的 fixed balanced coverage 在扩展空间里是否仍然有效；若大多数实例的最优继续集中于同几个候选，先把这个负结果保留。

## 4. M6-B — 第一个小型可学习性能模型

在 M6-A 的候选池与数据划分确定后，开始一个**低参数、低开发成本**的监督学习原型，不立即训练 LLM。至少比较：

- 简单手写 IR/Shape/硬件启发式；
- 使用透明特征的线性模型或树模型；
- 小型 MLP/图特征模型（有足够样本时）；模型规模、训练数据、特征提取和推理开销都记录。

模型的监督信号可以同时包括实际候选的 `log latency`、路径相对排序、以及高层动作的 `min_B latency`（仅训练集用完整池标签计算）。推理时只能访问**当前决策点已知**的信息：高层原始语义、Shape、合法变换及参数、目标机器静态信息、此前已合法执行并测量的探针结果。若为了取得候选高层/affine 特征而先执行一段 Lowering，必须记录这部分编译成本；禁止将未来 LLVM IR、最终反汇编、未查询路径的实测时间泄漏给决策模型。

数据划分必须按原始程序/独立模板和未见的 Shape 组合分组，不按候选变换或批次随机拆分。根据实际独立样本规模报告泛化边界；若只够作探索性拟合，就明确标为 pilot。禁止把 M4/M5 上已调过的规则与同一实例的“测试表现”当成真正泛化。

**决策目标优先于预测分数：** 即使某个模型 RMSE 更低，如果在相同预算下没有找到更快代码或减少优化成本，也不算研究成功。

## 5. M6-C — 开始可控的神经架构融合消融

若 M6-B 显示预测/探针分配确有增量价值，可以在小模型上对照三类输入表示，避免大模型工程先行：

- **B0 当前表示：** 只编码当前 IR 结构、目标硬件与待选动作。
- **B1 跨层级表示：** 附加上游高层语义锚点与当前 IR 的关联，使用最简单的池化/拼接或 Cross-Attention。
- **B2 持续状态：** 随合法 Lowering、变换及真实反馈演化的压缩神经状态，并与**重新编码完整历史**作为强对照。

控制模型参数量、特征提取成本、训练样本、候选池及实际预算。**在同样数据和实验条件下，先证明 B1/B2 超过便宜的拼接/重编码基线，才把持续状态或 Attention 定义为架构创新。** 对于 Operation 粒度的 N:M 溯源，可暂时只在少量受控变换上实现必要关系，不要求本阶段开发通用编译历史追踪系统。

当候选池与模型足够成熟后，再把策略从离线回放移入实际按查询次序编译/测量、能被墙钟预算中断的在线执行闭环。最终论文强调最终代码性能、有效搜索次数与整个编译优化成本。

## 6. 给本地 Agent 的实施顺序和验收

1. **M6.0（可以立即执行）：** 只读取 M5 已提交数据，实现“15 种固定四候选子集穷举 + 随机候选预算基线”分析，明确区分 fixed coverage 和 adaptive lookahead。不要改动 M5 已提交的实验结论和冻结规则。
2. **M6.1：** 选择更丰富的合法 A×B 动作空间；增加一到两个新程序模板及独立 Shape；建立可复现的数据采集与结果分析。使用原有正确性、快照和噪声规范。
3. **M6.2：** 有了数据以后，实现简单可学习代价/价值模型；用未见实例验证，和规则、随机、固定覆盖、阶段贪心、有限探针公平比较。
4. **M6.3（以证据触发）：** 试验最小跨层级表示交互模块，并作参数量/计算成本匹配消融；若数据规模或信号不够，明确记录限制，不人为训练复杂网络。

建议交付 `experiments/reports/m6-findings.md`、数据/策略配置、可复现入口、清晰的训练/验证/盲测划分及模型训练日志（若执行 M6.2）。先保证 M6.0 / M6.1 有可信结果，再展开 M6.2 / M6.3。不引入新的硬件专属优化依赖，不重写编译后端，不使用额外大规模集群。沿用项目现有约定：暂不计算产物 hash、不额外写单元测试；保留真实端到端正确性校验和失败记录。

**最重要的判断标准：** 如果扩展候选空间后的强静态/随机规则已逼近 oracle，那么复杂神经架构暂时缺乏性能价值；如果仍存在可观的前瞻决策损失，且学习方法在相同预算下能稳定缩小损失，我们才获得推进 MLIR 与 Attention 深度融合的实证依据。
