# IRLoom — 研究定位与待验证假设

**状态：研究草案，2026-10-18。** 本文定义研究问题和候选机制，不将任何设想表述为已经证实的创新。

## 1. 目标与动机

IRLoom 的唯一核心目标是：**在保证程序正确性和可控编译开销的前提下，提高目标机器上最终代码的运行性能**。我们希望探索一种适用于 MLIR 多级编译过程的学习型优化核心，使高层程序语义、跨阶段变换历史、底层实现信息及硬件性能反馈在编译中相互作用。

现有 MLIR / LLVM 能使用目标 ISA、调度模型、缓存参数及成熟的优化 Pass，也已有各种自动调优、强化学习及图模型方案。因此我们的创新不能简单表述为「编译器知道硬件」「MLIR 有多层」「加入 Attention」「模型选择 Pass」。真正的问题在于：**不同抽象层级之间的优化选择是否缺乏足够的协同，以及持续的跨层级表示是否能够改善相同预算下的搜索结果**。

模型架构可以包含图网络、结构感知 Attention、循环更新的潜在状态或其他机制。不要预先固定层数/比例。MLIR Dialect 可以混合共存；「跨层级」是抽象与变换关系，不等于固定的三层 IR 栈。

## 2. 研究问题

**RQ1 — 信息价值。** 在同一编译决策点，仅使用当前 IR 与硬件特征的模型，和额外使用先前抽象表示与变换历史的模型相比，哪一个更能预测后续候选的相对性能？增益是否超越只是增加参数量或更长输入上下文带来的效果？

**RQ2 — 搜索效率。** 给定相同的合法变换集合、候选执行测量次数和总搜索时间，跨层级信息交互能否找到更快的最终代码？考察 best-found latency、达到指定性能的测量次数、模型/编译开销与最终总成本。

**RQ3 — 反馈归因。** 低层执行出现资源压力或性能回退时，能否利用变换来源关系和历史决策，更有效地选择值得修正的早期变换，而不是重新全局搜索？

**RQ4 — 硬件泛化。** 通用优化机制接收机器能力描述和少量校准/实测反馈后，能否适应不同微架构？首先在常规 CPU 路径验证，再扩展到 ARM、RISC-V 或 Ascend NPU。跨平台是检验目标，不是 Phase 0 的硬性前置条件。

## 3. 三种候选机制

### 3.1 Persistent IR State（跨 Lowering 持续状态）

对某次程序优化轨迹定义：
- `I_t`：第 `t` 个阶段的 IR；
- `A_t`：已执行的合法变换及参数；
- `H`：目标机器的结构/能力描述；
- `M_t`：模型保留的压缩表示；
- `Y_t`：当且仅当完成候选编译与执行时可用的观测反馈。

概念性状态更新：`M_(t+1) = F(M_t, I_t, I_(t+1), A_t, H, Y_t)`。其中 `Y_t` 可以为空，不能假设每一步 IR 变化都伴随真实 Benchmark。

这是一个可训练、可更新、跨阶段复用的状态；但**先验证它优于无状态模型和重编码完整历史的模型**。仅提高模型复杂度不构成研究贡献。

### 3.2 Cross-Level Interaction（跨层级信息交互）

通过数据依赖、Region/Block 嵌套、优化轨迹和变换来源关系组织信息，使低层实现有条件地读取相关高层语义信息，或让性能反馈指向可能的上游优化决策。是否采用 Cross-Attention、稀疏图消息传递或其他机制由实验决定。

操作追踪可能出现 1→N、N→1、N→M 的拆分/融合关系。Phase 0 只要求**阶段级与轨迹级的可重复映射**；细粒度 Operation 溯源是后续研究任务，不应成为第一阶段的数据采集阻塞项。

### 3.3 Hardware-Aware Feedback（硬件感知反馈）

硬件信息至少区分：静态能力（ISA、向量宽度、Cache、核数、调度模型等）、微基准测量（可选）、候选代码真实反馈（延迟/吞吐及可选 PMU 计数器）。模型应学到依赖硬件的优化规律，但不要让优化核心依赖单个厂商的算子或私有 API。

真实性能反馈是稀缺且有噪声的；使用它前必须有统一的测量协议和正确性检查。编译成功、IR 规模下降、静态指令数减少，均不得代替最终性能证据。

## 4. 一个需要提前承认的理论边界

若当前 IR、编译器状态、目标硬件及所有后续选择已经完整确定，那么早期历史**未必提供额外的必要语义信息**。我们不能凭「Lowering 丢失了信息」就断言持续状态一定提高最优性能上限。

更严谨的假设是：在**有限模型容量、有限搜索预算、不完备代价模型、受约束的候选变换空间**下，历史语义与优化轨迹有可能改进性能估计、减少重复探索或提高回溯效率。实验应当检验这一增益是否存在，以及它来自哪里。

相关性不等于因果归因。若要声称某种早期优化造成后端性能变化，必须通过受控变换实验，而不是仅从注意力权重或回归系数解释。

## 5. 研究边界与阶段安排

**Phase 0：建立证据。** 选择一条开放、可复现的 MLIR→LLVM→native 路径，覆盖至少三类不同计算模式，采集 IR 快照、合法优化轨迹、产物指纹、机器描述和实测性能。验证有无足够的路径差异，以及历史信息是否值得进入模型。详见 [PHASE0_PROTOCOL.md](PHASE0_PROTOCOL.md)。

**Phase 1：建立公平基线。** 在统一数据集与搜索预算下比较手写启发式、当前 IR 特征模型、当前 IR+历史模型、完整历史重编码。优先使用小模型；把性能排序和搜索效果区别报告。

**Phase 2：验证架构。** 研究结构化来源关联、持续神经状态、跨层级信息交互和低层反馈修正高层决策；做严格消融。这里才决定是否使用 Transformer。

**Phase 3：跨硬件检验。** 将通用优化核心迁移到另一种 CPU 微架构、ARM、RISC-V 或 Ascend NPU，报告适配代价与未见工作负载性能。

实验出现负结果也要如实记录并调整方向，不以任何预先设定的加速比作为必须达成的目标。

## 6. 本项目明确不在 Phase 0 做的事情

不训练大语言模型，不创建新 Dialect，不重写 LLVM 后端，不引入大规模分布式训练，不开发多平台统一执行框架，不复刻已有庞大自动调优系统。第一步的工程价值是形成**可信的跨阶段编译—执行数据闭环**。

研究的新颖性始终需要持续与既有多阶段 RL、代价模型、跨平台知识迁移及等价搜索工作比对；当前文档不主张这些构想此前绝对无人研究。
