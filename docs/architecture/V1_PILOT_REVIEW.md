## 1. 阶段结论

N0–N3 已形成可工作的 MLIR 内耦合原型：真实 C++ 图提取/变换、A 的阶段专用稀疏 Block、B 的共享 Block+GRU、来源与检查点、独立输出验证和原生计时。N4/N5 已完成一次小型训练/比较流程，但它不是充分的跨阶段架构效果检验。

本次不重定位研究，不恢复 PGO 调权、局部函数属性搜索或“先证明简单方法失败”的门槛。继续沿 A/B 设计补齐实现和训练；性能负结果仍如实保留，不预言修复后一定加速。

## 3. 已确认的结构表达缺口

### 3.1 无序字节平均会确定性地抹去属性顺序

`encoder.py::Encoder.base` 将 name/type/attributes 拼接成字节，使用 mean embedding_bag。无论权重怎样学习，字节计数相同的字符串得到完全相同的文本向量。例如：

```text
affine_map<(d0, d1) -> (d0, d1)>
affine_map<(d0, d1) -> (d1, d0)>
```

两者分别表达恒等映射和转置映射，但字节频数相同，当前文本编码不能区分它们。其它图/数值特征有时可以提供区别，但不能依赖这种偶然补偿。这个问题影响模型观察，不等于 MLIR 执行器把两个程序算成相同结果。

### 3.2 有类型图进入网络时变成无类型无方向图

C++ bridge 输出 uses/defines/contains/cfg/call 等边，但 `encoder.py::edges` 丢弃 kind，将每条边添加反向边并用集合去重。桥接层的 uses/defines/argument/cfg 还没有记录 operand/result/argument/successor 的位置。

因此图拓扑不能可靠区分操作数角色。例如同样的两个 block arguments 进入 `arith.subi`，交换它们的 operand 位置仍得到相同的无序邻接关系；重复使用同一个值形成的平行边也可能被合并。这是确定的信息丢失，不是增加训练样本就能修复的问题。

**V1.1 第一项实现：** 复用现有 Encoder/SparseBlock 接口，加入有序结构特征和类型化、有方向的边。优先从 MLIR API 导出操作码、标量/聚合类型、维度、比较谓词、affine 表达式及各 operand/result/CFG 角色；用确定的结构 token 或有位置的序列编码处理未知属性。无需预训练大语言模型，也不必实现所有 Dialect 的完美语义解析。

保留反向传播边时使用独立 reverse relation，不能与原方向混为同一种。保留多重边及 operand 等位置属性；SparseBlock 的打分/消息计算实际消费 relation/position，而不只是写入 JSON。图仍保持按边计算，不构造全程序 N×N 矩阵。

在现有集成审计里加入最小结构夹具：SSA 重命名不改变结构；交换 sub/div/compare 的操作数、改变 affine 映射结果顺序时编码输入必须能区分。比较提取后的结构，不要求随机神经权重对所有语义变体都输出明显不同分数。沿用不新建单元测试工程的约定。

## 4. 来源账本与真正进入网络的记忆要分开报告

`driver.apply` 保存受控变换的来源关系到 transition/path_lineage；下一次 `observe` 则调用 `lineage.align`，按 anchor 重新建立关联。`A.aligned` 与 B 的 recurrence 实际读取的是 Observation.lineage，而不是整份 path_lineage。

目前跨 lowering 主要保留 module/function/body 锚点，内部 Operation/嵌套 Region 多为 unknown。A/B 并非没有记忆，但不能把记录了细粒度来源等同于这些来源已经进入跨阶段神经连接。

V1.1 应新增轻量可观测统计：每阶段和每种粒度的 known/unknown 数量、模型实际读取的保留状态、动作前后及 lowering 后的映射组成情况、状态失效/重编码数量。对能够可靠组合的受控变换接通实际 Observation；无法追踪的一般 lowering 继续保守刷新，不伪造 1:N/N:M。先不造通用全编译器溯源系统，也不以完美对齐作为继续训练的前提。

## 5. 训练实现的下一项修正

### 5.1 支持真正的多程序训练

当前 `pilot.py` 用 `next(...)` 只选择一个 train 程序和一个 validation 程序。扩展配置中的列表而不修改此逻辑，不会形成多程序训练。

同时，`training.measured_loss` 目前以 paths[0] 为基准，并对传入的所有轨迹两两排序；当前单程序用法没有发生跨程序误比较，但直接把多个程序的路径拼入同一调用会错误地把不同任务的运行时间排在一起。

按 `(program/input/workload, hardware, semantic/compiler configuration)` 分组，每组使用自己的默认或预定义参照，同组比较合法轨迹，再按预先定义的程序权重聚合损失。不能让一个程序因采样轨迹多就无意主导全部训练。失败和无有效标签组要显式处理。

### 5.2 覆盖多阶段决策，而不是只扩大重复次数

在现有 Polygeist 路径和受支持的原生 MLIR 程序中收集真实多函数/多区域完整工作负载。训练、验证、测试均保留独立程序族，其中应包含至少两个阶段有可执行非 advance 动作的轨迹；按前端兼容性和动作可达性选取，不按实测加速筛掉负样本。

报告每个 stage/action 的合法候选次数、实际成功执行次数、成对性能标签数与梯度覆盖。声明支持且参与正式结论的动作不能只出现在验证/测试中。保持未知操作编码能力，但将“从未训练过的动作”单独标为 action-OOD。

程序源码完整不等于大型程序。本轮 S0 只有 253–678 个操作，函数数包含外部声明。下一轮将更大真实来源程序的导入与训练并行推进，报告已定义函数数、区域/操作数、调用结构、有效动作位置和覆盖范围。不能复制 kernel 或添加无用代码凑规模；若更大程序受前端限制阻塞，先保留兼容性记录，同时用确实多阶段的完整程序继续训练，不把结果称为大型 C++ 泛化。

### 5.3 不把测量噪声当成动作偏好

目前 pairwise 损失对任意不同计时都强制给出胜负，包括很小或重复路径的差别。按预先约定的测量分辨率/不确定性处理 near-tie（跳过强排序或使用软目标），记录候选实际路径及相同产物的直接比较；遵守不计算额外产物 hash 的约定。不能从一次更快的样本生成强“赢家标签”。

第一版继续使用轨迹排序，不必引入 RL。当前 value/resource loss 只在末端监督，beam 按累计 policy log-probability 而不是 value 选中间分支，应准确描述这一实现；暂不把它宣传为充分训练的跨阶段未来价值搜索器。若以后使用 prefix/action value，使用同前缀、可比较 continuation 的标签再独立消融。

## 6. 保持可解释的修订与对照

不要同时改变全部组件后只报告一个加速比。至少保留旧 Encoder 开关/冻结 checkpoint，在同一新数据上比较：旧输入表达的 A/B 与结构表达修正后的 A/B；再进行同信息/同预算的连接消融。来源接通和图编码修正分别标记版本。

继续保留 `current_only` 的独立训练。`A_no_history` 和 `B_reset` 是对冻结模型的测试时干预，不等同于从头训练的无记忆模型；正式比较同时报告其用途，必要时在相同训练数据和种子预算下补充独立训练的 B 无持续状态版本。

所有这些方法仍可共享当前 IR 和合法的离散动作事件特征。称为“移除连续跨阶段记忆”，不要称为删除了全部历史；当前 IR 本身也可能反映已执行变换。

对每组对照保存动作排名、实际选中轨迹、IR/目标代码差异。若完整模型与断连模型最终选择相同产物，其时间差只能用于估计测量波动，不能归因于隐藏状态的效果。

## 7. 测量修正

现有独立 C++ 计时器是有用基础，保留。下一轮先冻结产物，再按轮随机/平衡交错 baseline 与各模型选出的程序，不用标签采集早期的一次 default 时间对比很久以后的神经产物。搜索选优后独立复测继续保留，报告采集/训练/推理/搜索和确认全部成本。

`trie` 当前进程约 0.9 ms，启动/输出占比较大。可用程序支持的更充分真实输入或预定义的重复工作单位提高测量分辨率；批量启动很多子进程只能降低总测量噪声，不能声称移除了每次启动成本。若无法获得代表性的计算负载，保留它作为正确性/导入用例，不用其小差异作性能主结论。

分开汇总 train、validation、test；三者混合几何均值只留诊断页。同一前端/后端的 default 是架构消融对照；独立 Clang 输出 oracle 目前是正确性参考，不是已经测量的强性能基线。正式性能另测相同工作负载的 native Clang -O3，必要时加入既有 LTO/PGO 对照，不改训练配方来“创造”模型收益。
