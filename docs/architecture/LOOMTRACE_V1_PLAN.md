# LoomTrace V1：用完整编译轨迹训练现有 A/B

设计日期：2026-11-01。基线为修复版数据恢复提交 `207a1a4`。本文件是**下一轮开发计划，不是已有训练成果**。先复用当前 MLIR C++ bridge、A（阶段专用 Transformer）、B（共享门控状态）、hierarchical-v3、角色化候选读出与正确性/测量框架，不重建编译器，也不重新执行历史模型矩阵。

## 0. 为什么需要改变监督，而不是再追加孤立动作标签

修复后 Puzzle 的旧最佳已测收益从约1.13×变为约1.025–1.026×。原始 273 条候选记录仍以中性效果居多；真正有益样本集中在少量程序。更重要的是，已有 `stage-q-v1` 的监督是“执行当前动作、后面全部 `advance`”的实际完整程序时间，**没有直接教模型前面的动作如何改变后续可用优化及其联合结果**。

本轮的核心变化仅是**数据及其匹配训练目标**：从固定后缀的孤立动作，变成由预先固定、与收益无关的行为策略采样的真实编译轨迹。不是二叉树，不枚举笛卡尔积，不预先为所有合法候选生成所谓最优标签；也不直接上 RL、PGO 或更换 A/B 骨干。

必须承认另一个现实限制：当前 Polygeist pipeline 只有 S0 内联与 S1 unroll2 两个可决策阶段，S2 仅观察，LLVM O3 可能抹去它们的大部分性能差异。**更好的监督不能凭空制造编译器原本没有提供的优化机会**。本轮应将“跨阶段动作确实存在、会产生不同且正确的最终代码”与“网络学习是否成功”分别报告。

## 1. 监督的严格定义：固定行为策略下的整条路径结果

对程序 p、固定输入/硬件/编译器配置，先取得正确的全 `advance` 产物时间 `T0(p)`。由一个**预先冻结、仅依赖当时可见 IR/合法候选的随机行为策略** `πb` 顺序采集轨迹：

```text
S0: 观察 I0 / 合法动作 C0 -> 按 πb 采 a0 -> 实际修改 IR 并完成 S0 lowering
S1: 观察 I1 / 合法动作 C1 -> 按 πb 采 a1 -> 实际修改 IR 并完成 S1 lowering
S2: 仅观察、advance -> 固定后端 -> 完整程序正确性与实测时间 Tτ
```

仅当完整程序通过独立 oracle 才有性能目标：

```text
y(τ) = log[Tτ / T0(p)]
Q^πb(s_t,a_t) = E[y(τ) | 该阶段所见 s_t、动作 a_t，后续按 πb 采样]
```

`s_t` 包含当前的 MLIR、此前的真实离散动作及 A/B 根据历史自身产生的连续状态；**不能包含未来动作、未来 IR 或最终时间**。不同模型各自从轨迹的 S0 起点计算其记忆状态，并沿实际 Observation 顺序更新，保持阶段间梯度。S0/S1 的**实际执行动作**分别获得一份由同一个完整轨迹结果提供的 Monte Carlo 监督；没有执行的其他候选不能假装也拥有 `y` 标签。S2 没有可训练的动作 q。

每条轨迹的终端时间只是一份**条件在这次随机后缀上的样本**，不是 `Q*`、不是最佳路径，也不是其他候选的反事实性能。即使两阶段共用同一个结果监督，它们仍是一条相关轨迹，不能当成两个独立程序样本。

**本轮统一使用一个固定的 πb**，不把默认后缀与随机后缀的标签混入同一语义 q；默认路径只用于 `T0` 与正确性参照。若将来引入第二套行为策略，必须记录且条件化策略身份/分开训练，不允许隐式混合。推理时按预测 q 贪心选动作，其诱导的后续策略已不同于 πb，所以改善没有理论保证，必须以真实端到端编译与正确性验证为准。旧 `stage-q-v1` 的 all-advance 标签/权重继续单独保留，**新目标须版本化为 `rollout-q-v1`**，不能把两种 q 混为同一数值或不经重新训练直接沿用旧 checkpoint。

这一做法借鉴了 LLVM MLGO 的轨迹记录与编译后反馈思想，但本轮采用离线、终端真实时间监督的有限行为策略评估，**不是**直接复制它的 policy-gradient / RL 训练。

## 2. H1：实现真正的顺序轨迹采集（先小批量）

### 2.1 复用真实编译器，不建通用搜索平台

以已经通过正确性验收的 `cleanup-positional-v1` 为**本批所有真实 Session 的显式编译器 revision**。创建根、checkpoint/fork、observe/apply/advance、默认和 finalize 均核对相同 revision，不能借用 legacy 可执行产物冒充新协议。

采样器在本阶段只读取当前 IR 和合法候选，固定随机种子、固定策略版本。例如 `advance` 约40%，其余从实际存在的非 advance 动作按类型/目标函数/区域结构分层采样；若无非 advance，就选择 advance，并如实记录。具体概率写入版本化 manifest，**不得观察性能之后改变比例或只保留收益正的轨迹**。每一步记录所选动作及其当时的概率、候选集合、阶段、前一动作和真实变换结果。选中动作失败时记录失败/计费，不给错误代码性能标签，不悄悄伪造一条成功历史。

训练域先从**现有已见训练程序与验证程序**按家族、两阶段合法性和正确性选一个小子集，例如4个训练+2个验证；不碰已观察测试作为新 blind，不因新采到的速度筛程序。小批量参考每程序最多16条完整轨迹、共不超过120个新增完整终端（含默认和失败尝试）；达到预算就输出已有覆盖，不自动扩张。这里是**训练链路和监督有效性 pilot**，不要求样本量足以证明泛化。

根默认与各成功轨迹的实际产物在同程序/输入/硬件组内同批交错计时，复用既有随机/反序和完整 stdout oracle；同一完整 ELF 的别名只测一次，但保留不同真实动作历史。旧恢复数据可用于正确性/结构参照，不能混入新 rollout q 的终端目标。新数据、原始计时、动作、图和最终产物留现有忽略缓存，仓库只提交配方、代码和报告。

### 2.2 数据记录至少足够回放并学习

建议记录 `trajectory-v1`：program/family/split/input/hardware/target/compiler revision/πb版本与随机种子；根默认及其原始时间；按时间排序的 `Observation -> chosen CandidateAction -> Transition -> next stage`；所选动作概率；最终 IR/ELF 产物关联、oracle结果、真实时间样本、实际编译/采样成本与错误状态。

可用现有 `Session.report`、`observations`、`transitions`、`history`，不做第二套图导出或复制大量二进制。序列读取必须可明确得到**行动前**的 Observation 和实际选中动作；检查点本地 ID 不得跨轨迹借用。失败轨迹不构造伪延迟目标。

数据质量不是“完成多少次计时”，而是报告：独立程序/家族数、完整有效轨迹数、S0/S1 真实非 advance 覆盖、实际不同 ELF、重复轨迹/中性比例、正确/错误比例、以及**同程序不同 S0 前缀能否带来不同 S1 候选和最终效果**。最后一项先报告观察证据，不要求对所有组合做完全因子实验。

## 3. H2：让 A/B 真正从一整条轨迹反传（与旧 q 分开）

保留现有 A/B、hierarchical-v3 和共享候选读出，新增训练协议版本 `rollout-q-v1`，使动作分数仍可被当前 `guided` 读取，但含义变为固定 `πb` 下的预期末端 log 代价。旧 `stage-q-v1` 代码/权重不覆写。

一条成功轨迹的模型计算顺序必须是：

```text
state=None
for (observation_t, actual_action_t) in trajectory:
    (all_action_scores, ...), state = model(observation_t, state)
    只读取 actual_action_t 对应的 q；记录这一阶段的预测
终端 y 已由实测给出
loss = 各实际决策阶段的 robust(q_t - y) 平均
```

可以使用简单、固定的 Huber/区间回归抵御计时噪声；不要在尚未构造同前缀可比随机后缀时，把两个不同轨迹的末端时间当成精确反事实强对来训练 ranking，也不额外开发 actor/critic、RL、策略梯度、复杂不确定性模型。**序列中 S1 的损失必须实际反传到 S0 的连续状态**（A/B有记忆版）；无连续记忆对照应该没有这条路径。不要为了减少计算直接 `detach` 跨阶段状态。

同一程序的多条轨迹按程序先汇总，程序/家族等权，避免重复 Puzzle 类程序撑大梯度。数据采样与训练随机数、权重初始化、输入特征、动作接口和更新预算在 A/B/独立无记忆版本之间一致；连续状态之外的离散历史仍都可见。

首轮只训练 **A、B、A_current_only、B_current_only**，先一个冻结种子和有限更新数（可沿用200次主训练步，记录真实样本暴露），必要时再做第二种子。不重新训练旧表示、旧损失、容量消融、全历史矩阵，也不立即要求大规模新 blind 评测。

## 4. H3：只做能回答问题的闭环验收

先验收一条包含**真正 S0 非 advance 与 S1 非 advance**的轨迹：新进程中顺序复现动作和所有真实观察，编译成相同正确产物；A/B S1损失对前一阶段状态有梯度；失效的状态和失败动作不会写入有效样本。若数据中不存在这样的合法路径，应如实说明**当前动作空间不足以形成联合训练案例**，不要通过复制算子、复制同一程序或放宽正确性伪造覆盖。

小批量结果分三层：

1. 数据层：完整轨迹、不同正确产物、多阶段动作组合及实际相对时间的覆盖，是否存在可以学习的联合效应。
2. 学习层：train/validation 的真实轨迹末端代价预测、选中动作预测、不同阶段梯度、记忆/无记忆差异；估计的是 `Q^πb`，有限轨迹时不宣称校准到真实期望。
3. 编译层：在已见开发程序上少量真实完整合法集合 raw/guarded 复现、正确性和最终执行时间。默认保护改善不算神经或记忆收益；不在本轮重复千次交错计时或声称新留出泛化。

如果训练能拟合但编译没有收益，进一步区分“策略从 πb 改成贪心后的分布变化”与“当前动作空间根本没有有效代码选择”，不要仅靠再训练回答。保留从本轮采样中观察到的负结果和错误候选。

## 5. 并行但不阻塞主线：改善真实工作负载与动作覆盖

现有 Polygeist C 路线在多个程序上 S0/S1 的选项过少，或交给固定 Clang O3 后生成相同的代码；大型 SQLite TU 仍导入失败。安排一个**有界的接入尝试**，选择已经有来源与正确性依据的完整、多函数/多区域较大程序；优先从现有 pinned LLVM test-suite 的真实程序中选择，而不是继续反复硬攻同一个 SQLite TU。若 C 前端受阻，可登记一个匹配版本的 MLIR-native 完整 workload 路线（如 linalg/IREE），但不要同时建设多个重型前端。

报告实际支持的图规模、函数/区域、两个阶段的可用优化动作、正确性及不同最终实现。不得通过复制小算子凑大图。若发现“现有动作不产生有意义的联合效果”，应单独提出**通用且有语义前提的 MLIR 新动作/阶段**版本化扩展（例如已支持 dialect 的融合/分块/向量化），并让全部模型共享，不按某个测试程序定制。动作扩展属于后续阶段，不与首轮轨迹监督改动同时混合归因。

## 6. 交付和停点

按 H1（采集）→ H2（训练）→ H3（有限闭环）分阶段提交并 push；大程序兼容性可与 H1 并行，不能阻止 A/B 学习主线。新增 manifest、真实轨迹数据 schema/collector、训练入口、简明报告，建议 `experiments/reports/architecture-trajectory-v1.md`。每一步实施不做无关测试脚手架、hash、全量 SDK rebuild、任意防御层或旧矩阵复跑。必须保留独立正确性、结构/动作身份、新进程序列回放、编译器版本与共同成本检查。

**首轮停止条件**：已具备真实、可重放的顺序 MLIR 轨迹；A/B 的两个阶段都能接受整条路径的末端监督且跨阶段反传正确；四模型完成小规模训练及必要开发域编译闭环；明确给出当前动作空间是否确实形成联合选择。若样本均中性或联合动作不合法，也要完成诚实的接口/覆盖报告后停止，不自动搜索新 benchmark、不无限迭代训练配置。正式扩规模和新 blind 评价需另行冻结。
