# G1–G3 审查：先修复语义失败，再解释架构收益

审查基线：`4bf7804b600a96738b54459f711f2abe72a058c4`。依据活动报告、语料报告、机器摘要、MLIR bridge 及编译/评价代码；本次没有在原实验机器重新编译、训练或执行。下文是待实施任务，不是已经查明根因或取得新的性能结果。

## 1. 本轮结论与优先级

G1–G3 已完成一轮有实际多阶段监督的训练。10训练/3验证/3测试程序、273条匹配记录不是以往只有PC1单组标签的情况；A在两个种子的训练S1上均为112/113方向正确，不能继续笼统说“A完全学不会”。但100/113对来自Puzzle的三个前缀；无记忆A为107/113、112/113，无记忆B在部分比较更好。因此尚无稳定的连续记忆增量收益，训练拟合也不等于部署收益。

三个新留出上，24个guarded结果都与默认可执行文件相同；raw正确路径没有可靠加速。该结论应保留。更紧急的是3次Spectral Norm raw和6个guarded内部候选出现输出不符。末端oracle成功拒绝了这些候选，但这不证明动作执行链本身正确，也不保证未检查输入安全。

**当前优先级：冻结A/B、权重、编码、损失、学习率、动作集合与旧结果，先定位语义错误；随后只用已有产物分析有效决策覆盖。暂不新训练、不再运行全部历史性能矩阵。** 这不是新的“神经网络必要性”门槛，而是编译器必须守住的正确性边界。

## 2. 错误证据与尚未知的事项

活动中的B-s23、B无连续记忆-s23、A-s47在Spectral Norm的N=10独立校验中，参考输出为`1.271844019`，候选为`1.000000000`。全部注册动作已执行、IR verifier通过，但输出错误。现有证据只限定到内联/循环展开/固定lowering及后端的组合，不能直接宣称是某个上游Pass的bug，更不能归因于A/B记忆机制。

模型只选择bridge注册的目标与动作，不直接生成任意IR。应把问题作为编译执行/语义检查链的缺陷排查；前端IR、变换前提、桥接调用、lowering、后端、源程序定义行为与oracle都在排查范围。错误路径的性能不得作为低延迟训练标签，不能训练模型去“绕过一个未修好的编译器”代替修复。

已知源程序是锁定官方test-suite中的`SingleSource/Benchmarks/BenchmarkGame/spectral-norm.c`，包含动态N、嵌套循环、数组累加和VLA。它们是缩减与覆盖检查的线索，不是已证实的原因。固定源/工具链/宏和无fast-math条件保持不变。

## 3. C1：不依赖模型的最小错误复现与隔离

### 3.1 先固定具体失败路径

读取原`failure-audit.json`、动作请求、每阶段前后IR、LLVM IR、命令与stdout。给3次raw及6个内部拒绝候选建立失败清单，按实际变换轨迹/产物关系去重；不能把3次失败直接当成3个独立缺陷，也不能未检查就假定全为一个缺陷。

不重训、不重新让模型挑动作。编写现有audit入口下的固定轨迹重放，准确重现至少一条已保存失败路径，再覆盖其它独立失败类别。节点ID是快照局部的：重放必须校验当时的IR身份并在新快照重新定位目标；不能跨分支硬套旧数字ID。

最小复现记录包含：原始程序/工具链revision、失败输入、oracle命令和完整输出、动作语义目标、每个边界IR、实际LLVM/链接选项。命令成功但输出错误应有独立的`wrong_output`类别，不只留下笼统的“没有正确终端”。诊断入口成功应表示证据已核对，不能把预期复现到错误误报为正确程序通过。

### 3.2 固定后缀，从最早产生差异的前缀定位

从同一原始导入IR构建如下受控路径，不跑模型：

1. 全advance默认路径；
2. 仅执行原失败的S0内联，随后全部advance；
3. 不内联时，对能够可靠对应到同一原始循环的目标单独执行unroll2，随后advance；
4. 原内联加原展开的完整失败组合。

如果第3项的循环只在内联后存在，就明确标记不适用；不得对另一个循环展开后伪称完整2×2因子实验。仍可比较“已内联前缀+advance”和“同一前缀+原展开”，确定展开是否是必要触发条件。

所有可运行前缀均通过同一固定标准后端完成后再校验。在必要边界保存更细的IR，检查实际变换前后语义，如循环界限/步长/cleanup、loop-carried值与yield、数组读写/别名、alloca作用域、参数和返回值映射。不要仅用“verify仍通过”作为语义证据。

可临时用不同后端优化级别、匹配工具的解释/执行路径或独立函数输出做错误定位，清楚标注诊断。正式比较的Clang -O3参数不改变；不能靠关闭优化、放宽浮点误差或删除检查宣布修复。

### 3.3 最小缩减、修复或明确隔离

保留原benchmark源码不动，在独立诊断文件中缩减失败IR/源码，仍保持可触发的输出差异。通过最小复现确定是IRLoom bridge误用接口/漏前提、固定版本变换问题、lowering问题，还是其它已证实原因。

修复应针对机制与适用前提。不得按`spectral_norm`文件名、模型名、seed或某个节点数字硬编码黑名单。未能立即修复时，只能对已有依据的风险结构/动作做显式保守隔离并记录覆盖损失；禁用某类动作是临时隔离，不等同根因修复。无法建立精确前提时宁可公开暂停该适配器的相关优化，也不能继续把它称为已验证合法。

若需上游revision修复，先取得可复现证据并核实具体补丁；使用独立、匹配的工具链缓存，不混链SDK，不顺手升级整套依赖。保存补丁与最小集成复现，不要求创建大型单元测试工程。

### 3.4 验收范围

对修复后的已知错误路径执行多个定义良好的正整数输入，至少覆盖原10/20/300以及小规模、奇数/偶数和不能被展开因子整除的边界（例如1、2、3、9、11、21）。不把N=0等可能不满足源码前提的输入当有效测试。

原默认、原错误组合、相关单动作组合均与独立原源码oracle比较；保留完整输出、退出状态和命令。实际兼容的其它旧程序做有限默认/受影响动作回归，复用现有32次匹配重放清单进行定向验收；不需重新训练或重跑所有模型。

模型、损失和权重不变，必要时最后用原冻结模型复现此前失败的3个调用；修复改变图或候选时如实报告，不能要求跨版本分数仍逐位相等，也不能改模型来回避测试。

检查guarded仍拒绝人为注入的错误/失败并返回已验证默认。此结果只是已有校验输入上的保护，不宣称对任意输入形式化安全。

## 4. 修复后的缓存与数据边界

不覆盖`campaign-v1`。新bridge/工具链/动作合法性用独立revision和命名空间。按受影响的变换机制查旧标签与轨迹，列明“已复核有效 / 需要重采 / 无法判定”；没有依据不得宣布全部旧标签无效，亦不能不审计就全部照用。

重新编译可能改变性能和候选身份，不能将新程序放回旧q标签下而仍称同一训练样本。仅对受影响的标签重新采集；是否重训等定位报告后决定。不在本轮使用已见测试的速度选择修复方案、模型或超参数；正确性回归当然可以重放已见测试，但之后不再称新blind。

错误日志、旧权重、原失败数据和旧否定结论全部保留。若早期工具只返回generic RuntimeError，补充IR/产物/命令的诊断关联即可，不重建通用异常或实验平台。

## 5. C2：用已有数据区分学习问题和候选空间问题

这项在C1之后或只读分析时进行，不是再找一个局部优化题目。复用273条匹配记录和原编译快照，输出按程序/前缀/家族分组的紧凑表：实际不同IR、LLVM、目标/可执行产物，正确/错误/未判定，测过的最优正确候选相对该组advance，以及各模型是否提出/找到该候选。全池外未测动作仍标未知；“已测最优”不是全局oracle。

特别区分：

- 变换未改变后端产物；
- 产物改变但未发现可分辨收益；
- 已测正确候选有益但模型漏选；
- 模型选择了此前未测路径；
- 路径产生语义错误，不能进入性能收益统计。

这些是对已实现架构的诊断，不以降低后端O3、放松门槛或改源算法制造收益。不同.o可能只差元数据；机器代码和完整可执行文件关系需要结合实际日志判断，不能只凭文件大小断言优化已生效或被消除。

学习统计同时给出程序/前缀/家族等权的结果，以及beneficial选择和harmful拒绝；不只汇总全部pair微平均。当前训练S0效果数为5/39/0，S1为3/127/12（有益/中性/有害）；186个训练记录中166个中性，且排序对受Puzzle主导。验证S1为0/63/6。由这些记录学会“不做有害变换”和发现未见程序的新加速不是同一个目标。

同时保留现有事实：现在已有真实S1学习，不能再写成“模型完全未训练”；但在当前数据、动作和预算下，A/B尚未优于无记忆对照或默认系统。既不预言增加数据一定有效，也不把这个有限结果推广成所有神经编译架构无效。
