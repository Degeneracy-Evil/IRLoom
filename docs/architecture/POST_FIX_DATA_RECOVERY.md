# cleanup 修复后的数据恢复：收束 C1–C2，回到 A/B 实验

审查基线：`b3edb1c00fde674f3c669abc30fd775cc6651a25`。依据 `architecture-campaign-correctness.md`、补丁、隔离构建与标签影响分析代码；未在原主机复跑。本文件只安排修复后的标签恢复，不新增架构或更换研究目标。

## 1. 已确认的结果与结论边界

C1 对已发现缺陷的修复可以收束。固定 LLVM revision 的 affine unroll cleanup 构建按 SSA 值替换 initializer，混淆了共享初值的独立 carry，并可能改动同值 bound。补丁改成按 initializer operand 位置接续主循环结果；独立 MLIR、原官方固定版本 pass、四种路径及多输入回归给出了相互支持的证据。这个结论限于锁定版本及已覆盖机制，不声称所有 MLIR/LLVM 版本存在该问题，也不声称已经证明所有变换正确。

旧错误结果和原回归原样保留。新工具链 `cleanup-positional-v1` 隔离构建，未修改原 SDK。当前72项输入、32条历史匹配动作、3个冻结模型及guarded故障注入构成已完成的验收，不在下一轮重新建设这些接口。

273条旧标签里13条机器码改变：Puzzle训练7条、DES验证6条。13/273虽不到5%，却触及65/113个旧训练S1强对；不能把旧112/113等拟合数字原样解释为修复版排序能力。旧标签是旧产物的记录，不倒改历史；新产物必须重新测量，也不能据当前修复直接断言旧Puzzle收益全为错误计算造成。

C2已有候选中有益组集中于PC1 S0、ReedSolomon S0和Puzzle三个S1前缀。后者修复后的性能未知，所以目前不能沿用其约1.13倍的旧比值。下一步的直接问题是：**在正确的工具链下，原有跨阶段训练偏好究竟保留、反转还是变得不可分辨？**

## 2. 冻结范围与版本

保留A/B、hierarchical-v3、角色化读出、shared-root-margin-v1、all-advance-v1、现有候选动作和采样轨迹。不要同时改变模型、学习率、训练步数、噪声门槛、PGO/LTO或输入规模。旧campaign、权重、报告和工具链不覆盖。

建立独立数据版本，例如 `campaign-v1-cleanup-positional-v1`，记录原数据版本、补丁/构建记录、实际bridge路径、完整命令、硬件/亲和性、pipeline manifest和测量批次。缓存查找必须验证协议与compiler revision；不能只换目录名或读取一个revision字符串就复用旧产物。

**Session默认仍为legacy。** 必须把新revision传到每个实际新建/分叉会话，并在观察、执行、根默认、后缀完成和后续raw/guarded入口核对实际manifest与bridge。不要假设顶层传入 `--compiler-revision` 后，所有已有campaign子入口自然都会透传；新数据入口须审计这一点。旧入口继续服务历史复现，不静默全局切换。

## 3. 一次有界的数据刷新，不只替换13个时间数字

### 3.1 以比较组为单位恢复

13条改变记录涉及Puzzle与DES。为避免同一前缀里新旧日期计时和根参照混杂，**本轮刷新这两个程序的原有全部比较组**：Puzzle36条、DES35条，共71条原轨迹记录，以及各自根默认。实际执行列表从原dataset和影响清单生成并核对，不另加优化候选、不据新速度筛路径。

复用已完成的13条修复产物前，核对来源、编译器revision、输入与原动作对应；其余路径用修复版重放或在已有充分的同revision产物证据下复用。节点编号仅在快照内有效，按现有结构定位和候选校验重放，不能硬套旧ID。

预注册执行清单上限为这71条路径加两个根默认；同产物与根默认别名去重并计费，失败保留，不自动追加新搜索。所有重建候选执行原有完整输出检查和对应正确性回归，错误候选不能获得性能标签。原来正确的候选若变错，停止该比较组进入训练，并报告新回归，不放宽oracle。

### 3.2 同批交错测量

将两个程序各自的根默认、各前缀advance和全部原已测候选放入同批测量。保留原输入、编译flags、单核与计时协议，按已有六轮随机/反向顺序交错；每次测量检查输出。测量期间不要同时在邻核训练模型或编译其它工作负载，以减少可避免干扰；仍明确说明频率及外部主机负载未完全受控。

程序内部按**完整可执行文件字节**去重计时，轨迹/上下文别名保留。只比较 `.text` 不足以证明其它段和重定位一致。新相对q使用本批根默认；前缀内的成对方向、canonical时间、分辨率、gamma、中性/有益/有害分类全部重新生成。不能只改13条的延迟，却继续使用旧pair列表、旧默认耗时或旧标签边界。

### 3.3 其余程序保留可追溯来源

其余202条原记录不在本轮重测范围，继续保留原输入与旧计时，标记为“依据C2机制审计继承的历史测量”，附未受本补丁机制影响的证据。不能伪称它们已经由新revision全部实测，更不能将“机制未受影响”升级为跨硬件/任意工具链的等价证明。

新dataset可以组织继承组和新测组，但每个比较组的参照、计时批次和来源必须自洽，不在一个组内混搭两个测量活动。若后续要求严格全修复版活动，再统一重建/复测；本轮不因版本整理自动重跑273条或历史所有矩阵。发现继承条件不满足的记录标记待处理，不能静默复用。

## 4. 更新覆盖，再解释旧模型

生成新旧差异表，至少包含13条重点候选的产物变化、每个受影响前缀的最佳已测候选、advance参照、可分辨有益/有害数、原强对的保留/反转/不可分辨/新出现情况。绝对运行时间跨日期差异仅作背景；性能关系主要使用各自活动内部的配对比较。

重算修复版标签的程序/家族宏平均。尤其区分训练S0、训练S1、验证S1；不要用一个大前缀产生的大量pair来代表独立程序多样性。新候选最佳仍只是已测集合最佳，不是全局oracle。

旧冻结模型可以用于一次**标签迁移诊断**：若决策前的图、候选语义、可见输入和来源关系与原记录确实一致，可用保存分数与新标签比较；有变化则以修复版观察重新前向并记录差别，不硬对齐旧数字ID。无论哪一种，都要标为“旧监督训练模型在新标签上的诊断”，不能宣称新模型效果或新blind泛化。

本轮不训练、不额外提出模型候选、不再次跑Spectral Norm/Ooura FFT/PI新性能主表。它们现已是正确性/回归材料，保留原失败与无收益结论。

## 5. 交付与恢复训练的边界

复用已有采集、标签和分析模块，新增最少的版本化入口；具体命令实现后写入RUNNING，未实现前不要声称可运行。交付建议 `experiments/reports/architecture-postfix-labels.md` 及必要机器摘要：

- 明确修复版工具实际生效，旧缓存和数据未被覆写。
- 71条原路径及两个根默认的尝试、不同产物、正确性和真实测量成本。
- 13条重点候选不再引用旧性能，新pair/gamma全部由匹配活动重算。
- 202条继承记录的来源边界，以及更新后的独立前缀/程序/家族监督覆盖。

这次数据恢复完成即可结束正确性修复支线，不再设置“必须先证明神经必要”的门槛。随后恢复原四模型的统一训练时，以新数据版本和明确修复版编译器为准，旧模型只作对照；初次比较保持同初始化/数据顺序/训练预算，隔离标签修复的作用。是否还有充足的跨阶段有益监督由恢复报告客观说明，不能预先保证补丁使A/B更快，也不能为了保留旧收益修改阈值。

更大真实MLIR程序接入和架构效果仍是主目标，本轮不另起PGO、单函数调参或LLVM旗标搜索。旧结果、负结果和失败全部保留，大产物用外部缓存，不额外计算产物hash、不新建单元测试工程；必要的集成、完整输出、版本/缓存与计费检查不可省略。
