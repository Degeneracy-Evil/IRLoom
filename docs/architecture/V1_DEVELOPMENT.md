# IRLoom V1 开发规划：从设计进入架构实现

本阶段以 [V1_DESIGN.md](V1_DESIGN.md) 为设计基线。历史 M0–M7、RealBench、PGO/Pmix 只提供基础设施和证据；它们的旧“下一步”和神经开发前置门槛不再是当前任务。

## 1. 范围冻结

必须交付一个真实工作于 MLIR 多阶段编译中的神经原型，并实现两种可替换计算核心：A 为阶段专用 Transformer，B 为共享门控循环状态。不是写出空接口，也不是再跑一个固定规则实验后停止。

首版只选一个 CPU 目标、一条原生结构化 MLIR 主路径、一套共同合法动作空间、一种共同有界搜索器。先实现单路径神经编译，随后增加相同预算的少量分支。ARM/RISC-V/NPU 迁移、Hybrid、强化学习、KDA/Mamba 专用 kernel 以后单独研究。

既有代码的复用范围是编译命令记录、版本锁定、运行器、数值检查、计时/失败处理和大文件缓存。旧的 workload 名称判断、固定 Shape 规则、手写动作优先序及正则表达式特征不能冒充架构模型。

## 2. 工作分层与目录

建议新增独立路径，名称可小幅调整，但不要破坏旧 CLI 和已提交结果：

```text
compiler/mlir_bridge/         # 小型 C++ 工具：真实 IR 图、阶段执行、检查点、来源账本
compiler/pipelines/           # 版本化阶段 manifest 与受支持变换
irloom/neural/schema.py       # Observation/Action/Transition/Measurement
irloom/neural/driver.py       # 编译会话、预算和 A/B 的共同编排
irloom/neural/encoder.py      # 局部图编码、函数/区域摘要、硬件特征
irloom/neural/interleaved.py  # A：阶段专用神经 Block
irloom/neural/recurrent.py    # B：共享更新器及分层状态
irloom/neural/heads.py        # 共同的动作/性能/资源预测头
irloom/neural/lineage.py      # 外部 ID、N:M 来源记录、状态对齐
irloom/neural/training/      # 轨迹数据、损失、训练与冻结模型
experiments/architecture/    # pipeline/model/data/budget 的锁定配置
scripts/architecture.sh      # 新统一入口；在实现前只是计划名称
```

不提前建空的插件生态、通用服务框架或新 dialect。不把所有新逻辑继续塞进 real_bench.py。大依赖、模型权重、原始 IR 与构建产物留在忽略/外部目录。

## 3. N0：锁定编译阶段和接口

**目标是可执行的数据流契约，不是又一次性能审计。** 以既有 MLIR 可运行链为起点，建立 architecture 专用配置，明确 S0/S1/S2 的入口不变量、必需 lowering、候选变换与默认路径。用真实工具版本确认 API/Pass 存在；必要时准备匹配 revision 的 MLIR C++ SDK，独立于旧实验工具链，按实际需要构建最小目标。

定义 Observation、CandidateAction、Decision、Transition、TerminalMeasurement，以及 snapshot/branch 的身份规则。配置中写清无动作/非法动作处理、步数/内存预算、编译后端选项和不允许改变的语义约束。

**验收：** 一个原生多操作 MLIR 模块能在三个观察点暂停、保存、继续；禁用神经决策后走既定默认路径，输出正确。日志完整标识阶段与命令。数据类型/ABI/浮点条件一致；不得宣称当前只是 CLI 可跑就等于架构完成。

## 4. N1：实现共享 MLIR bridge、图与变换闭环

C++ bridge 用真实 MLIR API 导出类型化节点、SSA/CFG/嵌套/调用关系。建立全局函数/区域摘要和局部子图；unknown 的别名、间接调用和不支持操作显式表示。模型输入不依靠匹配几个 benchmark 名称。

实现少量有类型、可作用于具体目标的动作。优先复用 Transform Dialect 和既有 Pass；不是无限增加动作数。支持候选适用性检查、检查点副本试执行、失败恢复与失效分析。若一项动作不适用于该输入，mask 或拒绝，不能偷偷换成不同动作。

建立函数/区域锚点，先精确处理自身控制的变换；一般 lowering 的细粒度关系未知时记录 unknown，刷新该区域。全局状态属于 driver；先在安全模块边界串行决策，不违反并行 OperationPass 的隔离约束。

**验收：** 至少两个阶段能执行不同的非 no-op 动作并实际改变 IR；恢复同一检查点后能重放动作；来源删除/拆分/合并不产生悬空目标；独立正确性验证通过。通过脚本覆盖一次非法动作拒绝和一次失败恢复，不额外扩建单元测试体系。

## 5. N2：完整实现架构 A

用 PyTorch 实现共享图编码器、阶段专用结构化 Transformer、跨阶段隐藏表示对齐及动作头。开发缺省配置可为 hidden=128、heads=4，每阶段一个 Block；保持配置化，不调几百组超参数。

A 必须接收变换后的 IR，而不是反复读取原始输入。神经输出必须进入编译动作执行器。跨层隐藏状态在训练轨迹中保持梯度连接，真实 compiler 仍是不可微的确定性外部执行器。

先对少量已生成轨迹验证 forward/backward 和损失下降，再将未充分训练的网络接入真实单路径编译。此步只检验实现，不要求速度提升。日志须展示每阶段模型输入、候选、输出、实际执行及后续 IR；冻结权重和随机种子可重放选择。

**验收：** A 能完成 MLIR -> 神经决策 -> MLIR 变换的多阶段闭环，生成正确机器代码；跨阶段连接确实参与梯度计算；关闭连接的消融可运行。若尚没有大数据，也继续完成模型实现，不退回旧的规则必要性调查。

## 6. N3：实现架构 B，并锁定共同实验接口

复用 N1/N2 的编码器、候选集合、动作头和训练记录，加入共享门控更新器及 module/function/region 状态存储。首版采用清楚可审查的门控/GRU 式状态更新，不写 KDA/Mamba 高性能算子，也不把它叫作已经实现了这些特定模型。

实现新节点初始化、删除节点处理、未知来源刷新、分支状态独立、重置/恢复。B 的更新触发时点与 A 一致。真实执行反馈只有完成相应候选后可见，不能把离线全池标签当成实时记忆输入。

**验收：** 仅切换 model=A/B 即可使用相同输入、阶段、动作与运行器。B 可做真实反向训练和完整编译。两分支交错执行不会串状态；完整重新编码与增量更新分别记录成本。开始时不要求两架构参数量完全相同，但必须记录并在正式对照中补容量匹配实验。

**N0–N3 构成首个核心交付包。它的完成标准是两套架构真的存在且可工作，而不是跑出一个正收益数字。**

## 7. 与 N1–N3 并行：真实程序进入 MLIR

原生小 MLIR 是实现 smoke，不是最终工作负载。大程序导入不能等全部模型完成才开始，也不能反过来阻塞两套神经核心。

首先使用一条锁定的 C/C++ -> MLIR 前端路径。首选对 Polygeist 做项目级接入，使用其要求的匹配 LLVM/MLIR；从既有 LLVM MultiSource 中选择语言特性受支持的完整程序。不能承诺每个 Zstd/SQLite/Clang 都能通过，不同时启动多个前端的大型建设。ClangIR 可在需要时作前端替代，不在同一首版里双线维护。

真实导入要求保留多函数/区域关系及端到端正确性；多 TU 通过符号、可见定义和调用摘要组织，在确能合并的模块范围内优化，外部定义标记 external，不要求一次实现全程序链接器。局部覆盖要报告进入 MLIR 的范围，不能当作整项目验证。

若 C/C++ 兼容性阻塞，则记录具体不支持特性，并并行采用现成 MLIR 原生完整程序路径（例如 IREE 的端到端模型/多区域程序）承载架构。导入和默认执行先验证，不重新开发运行时；IREE 与旧 MLIR 18 工具链不能混链库。模型路径与 C/C++ 路径分开报告，避免以完整神经网络模型的结果宣称已解决通用 C++ 编译。

**正式效果评估须有真实来源的完整、多函数或多区域工作负载，而不是把小 kernel 复制几千份凑行数。** 覆盖规模用函数/区域/操作数、调用边、动作数与热点分布说明。旧 Zstd/SQLite native 基线保留，但未进入 MLIR 前不计作 A/B 主结果。

## 8. N4：采集针对架构的轨迹并完成首轮训练

先固定训练/验证/测试程序族、输入和硬件；同一程序的变体、快照和重复测量不能跨 split。复用现有采样框架，生成合法的多阶段轨迹与完整程序真实性能、代码大小、编译耗时。采集保留默认路径、受控随机/均衡路径和模型探索路径，不能只保留赢家；非法变换保留失败信息。

不回到“证明历史有用后才收集模型数据”。需要学习的任务就是同一设计中不同阶段的状态传递和候选排序。先使用候选相对 log latency / pairwise ranking，并加资源代价辅助监督；观察有限 continuation 的值，不把池内最佳值冒充全局最优。

先在小数据上确认 A/B 都能学习，再冻结一次有明确预算的 pilot。数据规模按可承担成本扩展，不能把任意样本数当成架构成立的理论门槛。将源码/输入族划分、采样种子、模型参数、训练/验证曲线和标签获取费用写入配置与报告。

**验收：** A/B 均有保存并可重放的训练模型，在留出完整程序/图族上执行真实单路径编译；输出正确性、运行性能和全部编译成本。没有加速也是有效实验结果，但不能把仅在合成标签上 loss 下降当作最终完成。

## 9. N5：同预算架构对照与消融

先比较单路径，再使用共同的小预算搜索器。例：beam=2、每程序最多8个完整候选，具体数值在看正式结果前锁定。每个候选都从自身 IR/神经状态检查点继续。失败、重试、特征提取、模型推理、编译及真实测量均计入预算；全池后验最优只作参考。

至少包括同一 MLIR 前端/后端的默认流水线、只看当前阶段的网络、A、A 去除跨层连接、B、B 每阶段清空记忆或重新编码完整已知历史。既有启发式/搜索基线保留，但不阻止实施 A/B。

A/B 的共享权重和层数不同，参数量与推理量不可能默认相等。分别报告架构原配结果和容量匹配结果；相同可见输入、动作空间、数据、候选预算及总优化时间边界必须一致。不能仅因 B 参数更少或 A 搜索更多就声称机制更优。

分别报告：完整程序加速、几何均值与最差负载退化、编译/搜索时间、模型首次加载与稳态推理、内存峰值、代码大小、实际测量次数和训练摊销。硬件单机仅限单机结论。标准流水线启用何种 PGO/LTO 要写清并在对照中保持一致；通用 Clang 基线可以单独报告，但不能隐去前端差异。

结果诊断遵循四类：有运行收益且成本合理；同等性能但优化成本更低；无增量收益；有正确性或鲁棒性问题。只有这轮完整对照结束，才根据消融改架构、调整表示或考虑 Hybrid，不凭单个不利 benchmark 再重设研究主线。

## 10. 当前 Agent 的明确任务

阅读设计与本规划后，按 N0 -> N1 -> N2 -> N3 开发并小步提交；真实程序导入可以并行，但不得挤掉 A/B 核心。先复用旧小样例做 smoke，不复跑旧大矩阵、PGO 训练或 Pmix 调权。常规 API/构建问题自行处理并记录；某个动作或前端不支持时缩小适配范围，不改变核心架构，也不伪造支持。

每个里程碑附最短复现命令、实际验收结果和剩余限制。首个汇报必须区分“代码已实现”“端到端正确”“尚未训练充分”“性能尚未验证”。接口稳定后继续 N4/N5，在明确配置预算下执行；不需要再等待“证明一定有性能优势”的批准。

延续项目约定：不额外计算产物 hash，不新建单元测试工程；仍必须执行必要的集成 smoke、失败注入、数值校验和重放审计。大文件不进入 Git，旧结果不覆盖，不改系统安装或全局配置。模型训练以轻量单机起步，不自动部署分布式训练或改造集群。

本次文档交付后，下一次工作的重心是 **MLIR bridge + 首个 Interleaved 网络的可执行闭环**，而不是新的候选问题调查。
