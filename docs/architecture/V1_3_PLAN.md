# V1.2 审查与 V1.3：把程序内部结构真正传到决策读出

审查基线：`09407c46584ef71935f00f4ca38b198806c6f701`。依据已提交的 V1.2 报告、配置和源码；没有在实验主机重新编译、训练或运行正式性能测试。本轮另做了独立 NumPy 图层公式检查，它不是仓库 PyTorch checkpoint 或 MLIR 程序的复跑，不能作为性能结果。

## 1. 接受已完成部分，不重新寻找研究方向

V1.2 的阶段 q、计费默认保护、分支恢复、新进程重放及幂等缓存已经真实接通。DES guarded 的全部 16 个配置最终与默认可执行文件逐字节相同；其约 1× 的计时属于默认保护与测量波动，不是学习收益。PC1 继续是训练族，约 1.09× 不能当作新测试泛化。Puzzle 的 B-s23 raw 回退也出现在独立无记忆版本中，不能归因于连续记忆本身。

保持 MLIR、A 的阶段专用网络、B 的共享门控记忆、已注册动作、来源规则和共同 raw/guarded 控制器。不改成 PGO/参数搜索，不重做 N0，不增加 Hybrid/RL。现在不是继续修复“q 没接线”，而是检查已经接通的模型是否真的看到动作所需的上下文，并有足够正确的监督。

## 2. 一个可定位的架构限制：摘要节点不等于已汇总的函数体

相关实现：`compiler/mlir_bridge/main.cpp`、`encoder.py::SparseBlock`、`interleaved.py::forward`、`recurrent.py::forward` 和 `heads.py::forward`。

- bridge 明确导出 function -> region -> block -> operation，以及 call -> callee 的关系。
- 但初始函数节点只编码操作头部、类型/属性和有限数值特征，尚不是函数体的神经摘要；符号名称不作为模型特征，这是合理的。
- 每个阶段只有一次同步的稀疏注意力更新。所有边消息读取更新前的 x，不能在同一次调用里先让函数节点吸收函数体，再让调用点读取这个更新后的函数节点。
- 动作 q 的输入是目标节点 h、模块 h[0]、动作/参数。没有显式读取候选关联的被调函数体或循环体摘要。

因此，在 S0 无先前记忆时，调用点可以读取 callee 的头部，但不能沿多层 contains 链直接读到其 body。模块节点可以聚合全程序初始节点特征的总体分布，却不一定保留“哪一组内部操作属于这次候选调用”的对应关系。这个限制也影响循环动作：loop -> region -> block -> body 不是一跳。

这不等于整个网络看不见任何内部信息：全局向量含总体信息，后续阶段也可能有历史摘要。但首阶段的候选上下文存在一个可证明的盲点，不能靠多测几次同一个程序修复。

### 2.1 明确的结构反例

在同一模块中放两个头部/签名特征相同、内部计算不同的已定义函数 f、g。保留两份函数体、所有节点特征和其它关系，只把一个相同 call 节点的 `call -> f` 改成 `call -> g`。

对当前 A 的 S0 单 SparseBlock：若 f/g 的初始向量相同，call 的邻居向量输入不变；模块的全局初始特征集合不变。于是动作头读取的 h_call、h_module 和 action embedding 都相同，inline q 不能区别这两个情况。f/g 自己更新后的状态可以不同，但这一阶段的动作头没有读取它们。

独立公式级检查用 32 维、4 heads、三个随机初始化（17/23/47）构造以上图，均得到 call/module/q 差为 0，而其它图节点差非零。它说明信息传播路径的限制，不说明某个真实函数应该内联，也不说明正式 checkpoint 性能。Agent 应通过实际 bridge 生成的合法 MLIR 夹具和仓库 A/B 验证此现象，再用同一夹具验收修正。

## 3. E1：实现原设计中的分层摘要和候选相关读取

这属于共享表示/读出升级，不替换 A/B 的跨阶段组织方式。保留 `structured-v2` 为对照，新增独立版本，例如 `hierarchical-v3`。

建议采用清楚可审查的顺序，而不是单纯把所有节点 Attention 加深：

```text
当前类型化 IR 图
 -> 局部 SSA/CFG/操作特征处理
 -> 沿实际所属关系自底向上汇总 block/region/function
 -> 函数调用关系和模块摘要交互
 -> 针对当前候选读取其所属区域及关联对象
 -> 阶段 A Block / 共享 B 更新与共同 q 读出
```

可以把前三项实现为共享阶段编码器，再让 A/B 使用同一套输入；也可放入共同 StageBlock，但在文档中固定计算顺序。A 仍为阶段专用参数，B 仍共享更新参数和分层记忆。

**摘要必须由内容产生。** 函数/区域摘要应显式聚合其内部操作与相关数据流，而非只给空摘要 token 取一个名字。依赖未知部分带 mask；不要凭源码名字或目标 ID 记忆答案。汇总使用 contains 的层次关系，CFG 的环和递归调用不作为自底向上遍历的父子关系。

**候选读取具有角色。** inline 至少读取 callsite、caller、callee/body 摘要和模块上下文；unroll 读取 loop、其 body/访问结构和所在函数；advance 使用对应区域/模块状态。fusion 若仍只是 smoke，必须在覆盖中标明，不声称已训练。目标关系从 MLIR 接口和图结构导出，不按 benchmark 名称特判。

**保持可扩展性。** 一个函数的内部摘要为所有调用点复用，不为每个 inline 候选复制整份 callee 图；不构造全程序稠密 N×N 注意力。共享摘要计算和候选读取分别计费，未覆盖的巨大图明确失败，不静默截断。

**最小验收：** 实际 MLIR 上，切换相同头部但不同函数体的 callee，新的候选输入能够区分；只改 SSA 名字、等价的无序属性打印或会话 ID 不得改变结果。检查动作读出对关联 body 特征确有梯度路径，并保留已有错误恢复、分支隔离、重放与正确性 smoke。随机权重能区别两个输入只是结构验收，不是已学会正确性能判断。

B 写入/跨阶段继承的必须是已由内容汇总的状态。一般 lowering 的细粒度来源仍按已有保守规则刷新，不同时重写来源系统。当前函数体汇总是否有用，与跨阶段记忆是否有用分别消融。

## 4. E2：q 的损失必须允许真实代价成为正确解

`stage_learning.fit` 目前把同一个 q 同时用于区间数值回归和无温度、无截止的 `softplus(-s*(q_i-q_j))` 排序。排序方向正确；但当数值预测已等于实测 log 代价时，后者仍有梯度继续拉大差距。这是校准目标之间的张力，不是简单的符号错误。

一个不含噪声区间、两标签等权的说明例子：真实快慢比为 1.09，即 log 间距 d=log(1.09)≈0.08618。最优均值固定后，现有这种同权目标可写成

`L(z) = (z-d)^2/4 + softplus(-z)`。

最小点约 z=0.73457，对应比值约 2.0846，而非 1.09。这个例子只是数学诊断，并非正式模型必然预测 2×；真实样本数、共享参数和噪声区间都不同。但它说明未经缩放的排序 margin 不应直接被解释为真实 log 代价。

本轮采用最小修正，避免再引入第二套策略架构：保留区间 q 回归，将排序辅助改为在实测可分辨间距得到满足后停止施压的 margin loss；或者先用纯区间回归作为必要对照。举例，若 y_i/y_j 为标签，m_i/m_j 为冻结噪声区间，s=sign(y_i-y_j)，可用

`relu(max(0,abs(y_i-y_j)-m_i-m_j) - s*(q_i-q_j))^2`。

这样 q=y 时两个目标可同时满足；真实代码需统一 log 空间与原始计时的误差传播，不把毫秒阈值直接当成 log margin。旧 softplus 目标保留为受控对照，不能删除其不利结果。

只使用训练/验证标定辅助权重，不按 DES/Puzzle 表现调参。用可解析的两候选标签、相同产物零代价和真实训练子集分别检查校准。单看排名正确不够，报告 MAE、相对误差、advance 偏置与有害动作误判；未知/near-tie 仍不强制制造胜负。

## 5. E3：把工作量转向动作标签，而非更多空信号对照

V1.2 的 12 个 checkpoint、192 次搜索和 2040 次交错计时，不能代替训练信息。目前匹配动作终端只有 22 个（另有 6 个根默认），可靠排序只来自 PC1 S0 的两对，没有可分辨的有害动作训练样本，全部验证前缀也不可分辨。两对并不是两个独立程序。

采集器当前固定挑每个前缀的 advance、首个、最后一个候选；S1 只看根的 advance/第一个非默认动作产生的两个前缀。它有明显的结构位置覆盖限制，不等于代表全部动作，也不应被称作已经充分探索多阶段组合。

下一轮在采标签前固定一套有界覆盖配方：

1. 复用已能真实导入且有独立输出 oracle 的完整程序，并继续接入独立来源/程序族；根据兼容性、动作种类、函数/循环结构选取，不依据实测加速或网络表现挑程序。旧 DES/Queens/Puzzle 已经被观察，后续仅作开发/回归，不能反复宣称新 blind。
2. 小候选池可全覆盖；大池按动作种类、目标函数、循环层次作固定种子的分层抽样，不总取遍历列表两端。包含 advance。结构抽样的成本和候选覆盖分别记录，不采用未测性能筛选。
3. 对数个 S0 合法选择产生的真实 S1 前缀分别采样，不总依赖第一个候选。首轮可给每程序/输入约 16–32 个完整候选的上限，再按实际编译成本调整；这个数字是资源配置，不是成功或统计充分性的门槛。
4. 标签采集的默认与候选计时交错；共享同前缀/同后续策略进行比较。重复/near-tie/有益/有害都原样保留。覆盖不足时报告数据限制，不降低噪声门槛强造负例或筛掉无收益程序。
5. 先在少量模型上完成有效训练，再运行主要消融；不再对只有两对可靠标签的数据反复扩大模型/种子/冻结方法矩阵。七八种历史实现不必全部重跑。

本轮保持 `all-advance-v1` q 定义作为受控学习目标，不能把之后另选了动作的终端延迟当成此前 q 的匹配真值。它是固定后续策略的条件价值，不是全局最优联合价值。这仍限制其评价多阶段联合规划的能力。多 continuation 或有限后续集合价值属于另一个明确版本，不能在 E1/E2 同时悄悄改变监督语义。

按程序/家族及输入分组，训练前冻结新的验证与留出配置。验证组若全无可分辨候选，继续采用事先锁定的训练计划并标注不可评估，不从 test 找模型选择信号。完整程序源文件与正确性重要，但几千节点、十余个函数仍是中小规模原型，不足以支撑大型 C++ 全局优化结论。

## 6. 最小比较矩阵与归因

先完成 E1/E2 的确定性结构/损失验收，再冻结一次数据收集，不因某个模型初步好坏改变候选空间。

第一组隔离学习目标：同一旧结构编码、同一数据、同一 A/B 比较旧排序损失与新的校准损失。第二组隔离表示：使用同一校准目标，比较旧一跳读出与新增分层候选上下文。第三组才比较连续记忆：在新表示/相同标签/预算下比较 A、B 与各自独立训练的无连续记忆版；冻结断连是补充，不代替独立训练。

允许按小组顺序执行，不要求每组扩成完整历史模型×所有种子的笛卡尔积。参数量、实际受监督参数、推理/汇总成本分开记录。S2 观察-only/未受 q 监督的模块不能被当作有效训练容量；A/B 的额外容量差异不能算作记忆优势。

raw 与 guarded 均保留。默认保护、默认产物直接相同、共同 head 和共享摘要的收益都不能归为记忆。搜索控制器/预算保持固定，模型输出产物冻结后同轮重测默认，独立确认，保留失败/回退/不利指标。

### 审查的精确边界

本文件确认的是源码中的同步一跳读出、上述条件下的结构不可分辨性，以及 q 数值目标与无界排序目标的拉扯。未声称所有候选都不可分辨、所有已有记忆都无效、或者实际 MAE 都由排序损失导致。独立 NumPy 检查只作公式级辅助；需要本地 Agent 在实际 MLIR/仓库模型中验证。它不是新的 benchmark 成绩。
