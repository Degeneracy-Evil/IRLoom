# V1.3 审查与 V1.3.1：先验证完整训练，而非继续扩大对照矩阵

审查基线：`1f3a19fa1a12f9748ffe83fd44d0331dc0da9726`。依据 V1.3 报告、配置、stage_learning.py、cost_objective.py、hierarchy.py 和 label_timing.py；未在原实验主机复跑 MLIR、模型或性能。下面的100/97毫秒例子是独立复现源码标量公式的数学检查，不是新编译性能数据，也不是已读取全部本机标签后统计的发生比例。

## 1. 接受 E1/E2 工程成果，保留研究主线

共享内容摘要、角色化候选读取以及有限实测 margin 均已实现，报告提供真实 MLIR 夹具、数值检查、新进程重放及缓存幂等性证据。原来的一跳候选上下文盲点和无界排序目标已完成针对性修正，不重做这两项，不再从 N0 建接口。

Perlin 的分层 A/B raw 和所有 guarded 产物与默认逐字节相同，故本轮没有生成更快的 Perlin 程序；约1倍计时不是记忆收益。本轮也没有证明架构无效。A/B、hierarchical-v3、阶段 q、all-advance-v1 continuation、来源规则、动作集合和共同 raw/guarded 控制器继续保留。不增加新骨干、Hybrid、RL、PGO 调权或单函数属性研究。

当前最需要处理的是**训练选择与监督分辨率**，而不是立即再训练八套权重并做上千次测试。

## 2. 部署的八套权重实际上只做了一次优化器更新

配置冻结的选择是最低可分辨验证 regret、并列取最早；fit 每轮先 optimizer.step 再评估，只有 score<best 才覆盖 best_state。matrix 的四个验证前缀只有一个有害动作产生可分辨对，其余多数动作近似等效。所有方法在第0轮即取得最小 regret=0，之后并列不更新。

因此20轮虽然确实执行，但最终加载到编译控制器的八套 checkpoint 都只经历一次参数更新。epoch0 不是未训练的初始化，也不是完整20轮。第0轮隐藏连接/候选逻辑正常不等于模型已获得充分学习机会。

这是遵守旧冻结规则得到的结果，不是 Agent 偷停训练。旧的“并列取最早且不使用回归破平”计划没有处理这种低分辨率验证情形。现在应明确修订训练协议，而不是追责执行者或事后替换旧报告。

保存点的校准误差也说明其数值还未稳定：分层 A 的验证 log-MAE 为0.6251，末轮0.0945；B为0.1069，末轮0.0353。末轮误差下降不证明末轮会产生更快代码，也不能据 Perlin/DES/Puzzle 的性能选择末轮。这里要解决的是选择规则自身的退化行为。

### F1：采用独立版本的 fixed-final 训练主结果

本次小修订固定既有20次更新、学习率及数据，**主 checkpoint 预先指定为最后一次更新后的权重**。首先隔离“只部署一次更新”的影响，不同时任意增加训练预算。验证 regret、区间误差、MAE和动作稳定性都记录，但本次不按它们挑 epoch。不是宣布最后一轮总是最优，而是在当前验证几乎无法区分策略时使用明确固定的训练预算。

保存初始化（零更新）、第1/5/10/20次更新的 train/validation 输出与实际 optimizer-step 计数，末轮权重必须真实落盘。旧 earliest-best 只作为诊断副本，不改写 V1.3 已发布权重或成绩。不得根据任何 test/diagnostic 运行时间改变这条选择规则。

未来验证覆盖足够时，可另行冻结新的选模规范；不要在本轮又同时引入多种 early stopping/回归破平方案。

## 3. “可分辨标签”和损失使用的排序分辨率仍不一致

现在的根归一化 q 为 `y_i=log(T_i/T0)`。prepare_groups 分别传播候选和根默认的不确定量，得到每个 y_i 的 margin m_i；cost_loss 再采用：

```text
gap_ij = max(0, abs(y_i-y_j) - m_i - m_j)
L_pair = relu(gap_ij - sign(y_i-y_j)*(q_i-q_j))^2
```

有限 margin 消除了无界拉开分数的问题，真实数值是可行解。但**能正确容纳真值并不足以保证已标注的有效偏好被保留**。两个绝对 q 都使用同一个根参照，其差中的 T0 应消去；把两个独立根比值区间相加，会过于保守地丢掉部分已经判定可分辨的相对关系。

### 3.1 公式级反例

取默认 T0=100ms，两个候选为100ms与97ms；MAD=0，使用当前2%/0.05ms门槛。时间差3ms大于2ms，因此会进入强排序集合。

```text
y = [0, log(0.97)] = [0, -0.0304592]
每个根比值 margin ≈ 0.0400053
gap_ij = 0
q = [0, 0] 时，区间回归与有限排序的总损失均为0。
```

这意味着“全部预测无收益”在此例上已经是零损失解，尽管标签规则称其为可分辨的改善。候选顺序以 advance 在前时，打平可能最终选择默认。反例不说明实际 V1.3 的八对都发生此现象，也不证明这是 Perlin 无收益的原因；需从已有本地数据审计实际数量。

### F2：统一成对标签的判定与 margin，保留现有噪声门槛

先不重编译、不采新测试标签，从现有 dataset 输出：每组强排序对数、其中 gap>0/gap=0的数量、同q预测时的梯度和区间误差、根默认不确定量的贡献。区分原始轨迹数量、不同产物数量、成对标签数量和程序族数量。

新增版本化的成对 margin，直接在同程序、同前缀、同 continuation 的候选间计算：

```text
y_i-y_j = log(T_i/T_j)       # 共享的 T0 在差中精确抵消。
```

主方案沿用原 tolerance 所给的毫秒分辨率 δ_ij，不降低阈值。设 T_slow>=T_fast，且强对确实满足 T_slow-T_fast>δ_ij，可定义：

```text
gamma_ij = max(0, log(T_slow/T_fast) - log(1 + δ_ij/T_fast))
L_pair = relu(gamma_ij - sign(T_i-T_j)*(q_i-q_j))^2
```

它是原差值门槛转换到 log 比值的确定性分辨率表达，不是统计置信下界。对于同一组规范化时间，强对意味着 gamma>0，真q的差值能够满足它；near-tie 不强迫排序。不得用两个分别包含共享默认误差的 q 区间再次扣减 gamma。绝对 q 回归仍可保留现有根比值区间，两个损失的角色分别是数值校准和已确认的相对偏好。

对重复产物聚合/零目标的情况，强对方向、gamma和真q要从一致的规范标签构造，不能一边使用聚合后的 q 目标，一边使用另一个带噪原始排序。相同产物不产生强对。若采用逐轮配对统计替代组中位数，应单独标版本；本次优先最小公式修订，不修改性能门槛或暗改原始计时。

在仓库实际 Torch 目标中验收：真q仍是零损失/零梯度解；100/97ms例的同q预测有有效方向梯度；相同产物和不可分辨对保持中性；实际数据审计明确有效 margin 覆盖。该验收是数值契约，不是新的性能benchmark。

## 4. 实际监督规模与本轮结论边界

49个匹配动作终端包含PC1的12个、lists的15个和验证matrix的22个。训练实际只有27个终端，可靠动作偏好来自PC1 S0两种有益选择与中性选择形成的八个对；lists及训练S1没有可分辨排序，有害动作只出现在验证中。

因此，摘要和记忆可以接受数值反传，但模型尚未从广泛的跨程序、多阶段偏好中学到决策。120次编译、1320次评估重复不是新增训练集。要继续扩充真实程序和合法动作轨迹，但**本轮先用已存在数据把训练契约审清，不再机械重跑更大矩阵**。

这不是要求先证明简单规则失败才能训练网络。A/B继续开发和训练；诊断问题是网络在明确的有限监督上实际学到了什么，而非寻找另一个研究方向。

## 5. F3：一次小范围、可解释的训练验收

首先保留hierarchical-v3、共同q读出、硬件/来源接口和all-advance标签不变。在现有已冻结数据上做最小顺序比较：

1. 对A/B使用旧有限margin，但按fixed-final完成20次更新；与旧epoch0副本在train/validation上比较，只用于隔离选模问题。
2. 对相同A/B配置、种子、训练预算替换一致的pairwise margin；记录数值校准、强对是否选对、默认动作分数和不同前缀的实际动作，不用训练loss下降替代选路检查。
3. 修订训练机制稳定后，再用同一协议训练A/B对应的独立无连续记忆版本。无需重训所有legacy、容量变体、冻结干预和全部历史搜索矩阵。

每个阶段保留主目标、成对目标的分项曲线、有效梯度数和实际优化器步数。优先比较对训练组已知可分辨动作的选择是否正确、对未提供排序信息的组是否给出夸大的收益，以及验证有害动作处理。缺乏强标签的组注明无法评价，而不是宣布完美泛化。

若完整预算后连训练标签也未拟合，允许做一次预先固定上限（例如200次更新）的单组过拟合诊断，**只用训练组**定位优化器、数据/动作对齐、损失量纲或表示问题。该诊断权重不直接进入留出性能主表；过拟合成功也不是程序泛化证据。不要通过无限加宽模型、GPU或放松标签门槛解决。

本轮最终交付建议 `experiments/reports/architecture-v1-3-training-review.md`：先提供数据审计、实际步数/选模、损失一致性与少量train/validation的真实编译重放。可以复用旧Perlin/DES/Puzzle做明确标注的回归诊断，但它们已经被观察，不能称为新的blind。正式新泛化实验另行冻结输入与协议，不在本轮根据其成绩改变训练或选模。

## 6. 边界、后续和交付

本轮是V1.3.1训练修订，不是V1.4新骨干。E1摘要/角色读取和E2无界排序修复保留，其不足是监督分辨率尚未一致，不重复已经通过的基础开发。

更大真实MLIR程序、非中性多阶段动作标签和更好的验证集仍是下一步重要工作；选择应基于来源、兼容性、独立正确性和结构覆盖，不按哪种网络能赢筛选。新采样不要求人为凑出固定比例的正负标签，完整保留中性/失败/不利结果。

不改变q的continuation含义，不在本轮加入多continuation、RL、PGO或新的回溯算法。all-advance教师只能说明该完成策略下的价值，不能据此宣称学到完整联合优化最优值。默认保护与连续记忆的收益继续分开报告。

延续版本隔离、旧数据/权重原样保存、大文件外部缓存、独立数值正确性、重放和恢复审计；不额外计算产物hash，不新建单元测试工程。新增数值夹具使用现有audit入口。源码/训练结果/配置提交，但不要为本轮再自动运行所有历史raw/guarded和上千次确认矩阵。

**本轮验收重点：最终用于编译的是明确完成训练预算的权重；被标为可分辨的偏好不会在损失里无声退化为打平；模型在已知标签上的学习行为可以解释。** 之后再用充分、独立的程序监督评价A/B与记忆。上述修订不承诺留出加速，也不将当前无收益结果撤回。
