## 1. 结论：保持 MLIR 和 A/B，不再换研究问题

V1.1 已修正顺序、关系类型、方向、端口和 DLTI 非确定打印问题，并有新进程重放证据。接受这些工程进展，不重新从 N0 开发，不重复旧结构修复。

本轮确实没有证明连续记忆的性能收益。留出速度比 A/B 约 0.9485/0.9459；主要回退在 Puzzle，约 0.899 倍速度即约 11% 的执行时间增加。A 与断连 A、B 与重置 B 在 Puzzle 上分别产生相同可执行文件；因此这次消融不能把该回退归因为连续记忆本身。原生计时不含 Python/PyTorch 驱动启动，不能用模型加载慢解释产物运行退化。

这不是重新禁止神经开发的理由。下一轮保留 A 的阶段专用 Block 和 B 的共享状态更新器，修正它们共用的**性能监督、决策读出和搜索器**。未知收益如实报告，仍围绕既定架构做实验。

## 2. 已确认的三个断点

### 2.1 有性能训练的 policy，不等于已经实现阶段未来价值决策

`training.py::measured_loss` 在完整轨迹上累计选中动作的 log-softmax 概率，用端到端延迟排序训练 policy。该 policy 确实获得了性能监督，不能误写成随机或未经训练。

但 value/resource 变量在阶段循环中覆盖，回归损失只使用最后阶段输出。`search.py::beam` 虽计算各阶段 value，却只用累计 policy log 概率剪枝；value/resource 不参与分支排序。当前核心更准确地说是“带终端辅助回归的轨迹偏好策略”，还没有实现设计中“在每个阶段预测后续代码性能并据此选择动作”。末端 value loss 反传到较早状态，不等于较早阶段的 value 读出得到可校准的监督。

此外，父状态的 log-softmax 归一化常数不同。累计概率是完整策略路径概率，不是可跨不同候选数、不同状态直接解释的性能值。不能通过简单把未经训练的中间 value 加到概率上就修复这个问题。

### 2.2 决策标签和模型选择仍集中于一个程序

三个训练程序各采五条轨迹，其中 LLU、Bubblesort 没有超过冻结阈值的排序对；PC1 有七对，且这些对来自同一小组轨迹，不是七个独立程序。其余训练数据仍有 value/resource 监督，不能称为完全未训练。

验证程序 Towers 的强排序对为零。按当前损失实现，验证损失此时只有终端 value/resource 项，故选择 epoch 不直接考察候选动作排序或最佳选路质量。一个 checkpoint 的预测回归误差更低，不代表它选出的代码更快。

1200 次正式交错计时主要用于对照测量，并未转化为1200个独立决策标签。不能把增加计时重复当作解决训练信号覆盖的方法，也不能降低阈值强行制造标签。

### 2.3 搜索没有保留默认路径，配置上限不等于实际覆盖

`beam` 对所有分支按模型概率剪枝，没有保护全 advance 的默认路径；末端只从存活且实测的候选选优。因而即使默认编译产物更快，它也可能不在候选中。需要读取 Puzzle 的已保存轨迹确定默认路径在哪一步被丢弃，不能仅凭最终退化断言具体原因。

`beam_width=2` 在每个阶段都把 active 截为两个，末端再应用 `max_terminal_candidates=8` 仍最多只有两个终端。因此54组各两个终端与代码一致，不是“测了八个候选还选坏”。这个上限没有实际形成八候选探索。

## 3. V1.2-D1：先用冻结模型做决策链路审计与共同保护

不重训、不改旧数据，先读取原有单路径/beam轨迹，按程序输出每阶段排名、advance 名次、动作、候选数、存活/剪枝原因、最终 IR/目标/可执行文件的直接相等关系。对 Puzzle 追溯“选择了何种变换、默认是否被剪掉、两个终端是否独立实现”。此项只作诊断，不把测试案例用于定制模型规则。

保留两种明确区分的执行模式：

- **raw proposal**：单路径模型直接输出，用于评估模型本身的选择能力；不因结果差而替换数据。
- **guarded search**：在共同的完整候选预算内，保留一个真实默认产物作为 incumbent，并与模型提出的候选用相同协议比较。默认编译、校验和计时都要计费，不能作为免费额外候选。所有 A/B/无记忆/旧policy 对照采用相同规则。

先选择一个可承担的小型共同预算，不要求花满原配置的八候选；报告实际不同轨迹、不同产物、实际测量数与总成本。默认席位与普通 beam 前沿分开管理，避免再次被模型剪掉。选择与独立确认测量分开；无可分辨增益时按预定规则保留 incumbent。

这只是部署保护和搜索对照，不是神经架构创新；即使 guarded 取消了退化，也不能把它宣传成记忆收益。噪声和分布变化仍可能使独立复测变差，不承诺性能永不退化。遇到超时/变换失败返回可用的正确默认产物，同时公开未完成测量与预算情况。

## 4. V1.2-D2：共享的阶段动作价值头，而非再换 A/B 骨干

新增一个受控的 decision head 版本，输入为当前阶段 A/B 隐藏表示、目标区域、候选动作参数、可见硬件与已知反馈。输出明确有单位/参照的未来代价，不把任意 policy 概率叫性能。

令 p 是当前编译前缀，a 是本阶段合法动作，c 是事先冻结的后续完成策略，T0 是同程序/输入/硬件的默认完整流水线延迟：

```text
q(p, a, c) = log[T(完成 p、a 后按 c 继续编译所得程序) / T0]
```

越小越好。T0 是训练标签的组内归一化参照，当前测试未测候选的真实时间不能进入模型输入。使用统一根参照，是为了让同一程序不同前缀/分支的预测可比较；不能把不同父节点各自的局部收益直接当作同一量纲的全局分支分数。

初版只固定少量共同 continuation，例如全 advance 与一种确定的合法 balanced continuation。它们是相同的完成规则，不是跨不同 IR 强行复用旧 node ID。可在输入中明确 c，或按预先规定的相同分布学习平均 log 代价；必须说明选择哪一种，不能依据测试效果临时切换。预测的是有限完成策略下的值，不是全优化空间 Q*。

在同一真实检查点处分叉，比较 advance 与若干动作，使用相同的后续完成策略，实际生成并执行完整程序，得到**阶段可归属**的监督。共享前缀只计一次，后缀编译和测量如实计费；不必为每个节点穷举所有路径。覆盖 S0、S1 的不同前缀，使跨阶段交互有机会进入训练，而不是继续每个程序只采少数互不匹配的整条随机路径。

对 A/B/current-only 使用完全相同的数据、候选和 head。原有整轨迹排序policy保留为基线；新增 q-head 应在可选择动作的阶段得到监督，并在对应实验中实际用于 proposal/beam 排序，不只是增加一个不用的辅助loss。末端测量仍决定最终候选优劣，q 只是引导器。

可以用组内相对代价回归配合阶段候选排序；near-tie 是中性/不确定监督，不应被迫二选一。支持“执行动作有害、近似无影响、有益”三类情况。相同产物继续跳过虚假的强排序，但保留相同价值约束。任何风险/置信策略只从训练/验证校准，未经校准的分数不得称为概率置信度。首版不需要 RL、ensemble、复杂不确定性算法或自定义 kernel。

跨层隐藏连接保持可微；编译器动作与真实运行仍不可微。训练完成后直接检查改变 q 预测会改变实际动作排序，避免再次出现“输出有头、控制器不用”的断层。

## 5. V1.2-D3：围绕架构建立有效训练和模型选择

程序接入、候选合法性和输入设置在查看正式性能标签前冻结。程序按真实来源/家族分组，选择依据兼容性、独立正确性、结构和动作可达性，不按哪种网络更快挑程序。优先利用既有 LLVM MultiSource 的完整程序，并在固定 Polygeist 路线上做小范围可回归的兼容修复；不复制小算子凑行数、不改写算法来掩盖前端不支持。

明确区分三种覆盖：程序数、真正包含两个可决策阶段的轨迹数、每阶段可分辨的动作效果标签。不是只在配置中增加几个程序名。多阶段样本比例和各动作监督情况都要报告，但不再设“证明神经必要”的前置门槛。

当前 Queens/Puzzle 已被用于定位问题，下一轮保留为固定回归/诊断，不用它们挑超参数或证明新方法首次泛化。增加未用于架构修正与选epoch的独立家族；所有快照、分支和重复计时随原程序一起分组。

checkpoint 优先按验证候选选择质量与同预算 regret 选取，value/resource loss 为辅助。如果一个验证组所有候选都落在噪声内，该组记为“不能区分排序质量”，不能据此宣布策略已优，也不能让纯资源拟合悄悄成为唯一的性能选择标准。在整批验证信号不足时，采用预先冻结的训练轮次/选择规则并如实标注，另扩展预注册的验证组，而不是从 test 偷找信号。

大程序支持仍是正式目标。六个121–678个MLIR操作的小程序只适合验证实现/训练机制，不是大型全局优化证据。并行推进至少一个有真实多函数/多区域复杂性的完整输入；记录导入覆盖和失败原因。前端问题不阻止 A/B 共享决策修正，也不再触发另起纯 LLVM/PGO 研究线。

## 6. V1.2-D4：区分控制器收益与记忆收益

先在同一冻结数据上比较旧 policy 读出和新增阶段 q 读出，所有方法使用共同动作、预算和 protected baseline 规则。再比较 A/B 与分别独立训练的无连续记忆版本；冻结模型断连/重置继续作为机制干预，不能替代独立训练基线。

最低报告分成两层：

1. 模型层：raw proposal、阶段 q 排名/校准、advance 选择、不同产物、未见程序效果；
2. 系统层：guarded search 最终程序速度、默认回退率、候选覆盖、实际编译/测量成本和独立确认结果。

如果只有保护默认路径带来改善，应归因于搜索保护；如果新 head 对所有记忆/无记忆版本都改善，应归因于训练/决策闭环；只有同条件下记忆版本有额外收益，才能讨论跨阶段记忆贡献。

控制模型容量、编码器版本、来源规则和训练预算，先不同时更换字符串编码/图层数/隐藏维度/记忆公式。增加多个预先固定的训练种子，尽量冻结产物后复用共同交错计时；不重复构建全部历史模型矩阵。保留所有回退和失败。
