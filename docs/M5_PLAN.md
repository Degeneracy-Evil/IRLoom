# M4 研究审查与 M5：跨阶段前瞻优化

**审查日期：2026-10-18。** 基于 IRLoom `main` 的 M4 结果和实现进行只读源码/数据审查；没有在原实验主机重新运行。下文是研究任务设计，而非证明任何学习型编译器已有加速收益。

## 1. M4 真正证明了什么

M4 在 `linalg` 层选择循环顺序（A：`ijk` / `ikj`），在 `affine` 层选择后续动作（B：`none` / `tile16` / `unroll4`）。两轮重编译和测试均 21/21 正确，总计 630 个批次计时样本，顺序效应与低层动作的交互在中、大尺寸重复出现。

**更有价值的现象是高层的最优选择依赖于允许采取的后续动作。** 在 `127×65×93` 中，如果后续 B 固定 `none`，选择 `ikj` 更快；若 B 固定 `tile16`，反而 `ijk` 更快。高层如果仅按无后续优化时的延迟作贪心选择，再于该分支内选择最好的 B，就会错过 `ijk+tile16` 这个全局最佳候选。

直接基于 `m4-interaction.json` 的每轮候选中位延迟，构造**离线**对照：先根据 `B=none` 的实际延迟选择 A，再在选中 A 的全部 B 中挑最优；把结果与全部 2×3 候选的最优值比较。两轮结果如下：

| Shape | 贪心高层选择 | 贪心路径下最优 | 全池最优 | 贪心延迟 / 全池最优 |
| --- | --- | --- | --- | ---: |
| 32×32×32 | ijk | ijk+tile16 | ijk+tile16 | 1.000× |
| 127×65×93 | ikj | ikj+none | ijk+tile16 | 1.239× / 1.231× |
| 1024×256×256 | ikj | ikj+none | ikj+none | 1.000× |

这里的 1.23–1.24× 是**受控候选集合中的离线贪心损失**，不是训练模型或在线优化器的加速比，更不是与等预算全局搜索的公平对比。不要把它宣传成相对 LLVM 或主流自动调优器的提升。

M4 的另一个重要结论是：当前 `affine` IR 已经保留了 `ijk/ikj` 的访问顺序。因此仅凭 M4 **不能**证明保存上游 IR 历史比读取完整当前 IR 更有价值。观察到交互，不等于必须拥有 Transformer、持续神经状态或 Attention。

实现审查还显示 `--affine-loop-tile` 可作用于多个循环 Nest（含输出初始化）。受控变量是整个 Pass 在当前 IR 上的作用，不能单独把速度变化归因于 matmul 主循环的某个微架构瓶颈。反汇编呈现 packed 与 scalar 运算差异，但向量化未经过独立消融，不能确定唯一因果解释。

## 2. 调整研究焦点：先研究跨层级未来价值，再决定持续状态如何实现

从当前证据推导出的更直接问题是：

> 一个高层优化决策，能否在尚未完整编译并执行全部后续候选时，根据程序结构、可选后续变换与硬件特征，预测哪条路径最终有潜力达到更好的性能？

定义当前高层状态 `s`、高层动作 `a`、目标硬件 `H`、合法后续决策集合 `B(s,a)`，理想的高层价值为：

```text
Q*(s, a, H) = min_{b in B(s,a)} T(Codegen(b(a(s))), H)
```

`Q*` 是一个无法低成本精确求解的参考目标，而不意味着我们必须穷举或把它视为可微函数。研究目标是用小成本估计未来潜力，指导高层选择与后续搜索；模型结构可以逐步探索。

**重要的理论约束：** 若完整当前 IR 和目标状态足以决定后续合法变换空间，早期历史不一定携带额外的语义信息。持续神经状态的合理价值可能是：压缩昂贵的跨层级特征、保留试过的候选及测量反馈、帮助回溯高层选择，或者重新访问已降低掉的高层优化机会。不要把“必须证明历史 IR 对当前 IR 有额外信息”作为唯一研究路径。

## 3. M5 实验任务（Phase 1 的第一个里程碑）

### M5-A：先完成现有候选池的决策分析

以已提交的 M4 JSON 为输入，**不重新跑 Benchmark 也能完成**以下内容：

1. 输出每个 Shape 的全池最优、按 B=none 选 A 的离线贪心结果、贪心损失，以及每个 A 的最优下游 B。保留两轮值，标记微小差距与测量波动。
2. 明确区分高层动作对低层收益的交互量 `D` 与「提前作高层决策实际损失多少」。有交互不必然存在贪心损失，正如大尺寸所示。
3. 将不同候选的编译与计时成本分开记录。全池 oracle 只能作为可达到的性能上界（延迟下界），不计为可在线部署的优化器。
4. 给出一条非常简单的静态可解释启发式（例如循环顺序/访问连续性/Shape/预计分块规模），指出它在何种情况下能正确选路，哪种情况会失效。

### M5-B：少量扩充可学习的独立样本

沿用现有工具，设计**至少一个额外的非 matmul 程序家族**，其中真实存在高层 A 与较低层 B 两个合法决策点（例如可在 linalg 级进行交换或融合的结构，再配合 affine 级变换；实际 Pass 必须先用本机 MLIR 18 验证）。同时给 matmul 选择一组更丰富的 Shape，包含非整齐、方形、长宽比不同的尺寸。避免只在三个旧 Shape 上训练和测试。

优先扩展**独立程序实例与优化组合的多样性**，不是继续对相同 21 个候选无限重复计时。每个候选依旧执行真实编译、参考正确性校验、多次延迟测量与快照采集；保持兼容原有记录 schema，必要时增加版本化字段。继续允许失败候选被记录和剔除。生成成本控制在本机可承担的水平。

### M5-C：小型前瞻决策基线

在同一候选集合上，比较以下**信息可见性**和**优化预算**明确的策略：

- 静态启发式：只从当前 IR 的循环/访存结构与 Shape 选择动作。
- 无前瞻的阶段式贪心：早期用简单低层默认实现估计 A，然后固定 A、决定 B。
- 有限前瞻：每个 A 允许少量下游编译探针/候选评估；可先从规则或简单统计模型出发。
- 最佳已测候选（oracle）：仅作为离线性能上界，不参与同预算排名。

离线选路实验可先用已有的完全测量候选池模拟，并**清晰标注离线**；不得直接把全池真实标签喂给待比较的决策器。每种策略实际使用多少次编译、多少次真实执行测量、额外推理/搜索开销都要统计，并用相同预算比较最终找到的最好延迟。

如果数据量和独立家族足够，可以引入**小规模透明模型**预测最终候选排名或 `Q*`，但不急着做 Transformer。输入可来自当前/高层 IR 与硬件静态参数；按程序家族或从未出现过的 Shape 群组划分评估，避免把同一程序的不同变换或两次计时泄漏到训练/测试两侧。单机数据不允许宣称硬件泛化。

### M5-D：评估是否真的需要架构级创新

整理 B0/B1/B2 的小型对照，但要准确区分它们的目的：

- B0：当前 IR + 目标信息 + 计划执行的候选动作；
- B1：B0 + 上游高层语义/抽象特征；
- B2：B1 + 历史优化动作、分支搜索或已实测反馈（只允许决策前可见的信息）。

分析 B1/B2 是否在**固定参数量、合法动作空间和优化预算**下提高选择质量。如果提升来自多次测量或更大输入，应如实归因。持续状态与 Cross-Level Attention 是**后续实现 B1/B2 的候选架构**，不是 M5 的预设胜者。

## 4. M5 交付与停机条件

交付 `experiments/reports/m5-findings.md`，其中至少包含：现有 M4 的离线贪心损失分析、一组新的独立程序实例的受控 A×B 交互结果、静态/贪心/有限前瞻的同预算对照、真实成本统计，以及支持或削弱“跨层级前瞻优化”假设的结论。提供单入口复现实验/分析，不需要建立完整神经编译器框架。

优先实现 **M5-A**（纯分析，快速），再实现 **M5-B**。只有新增场景确认存在可利用的规划收益后，才投入 M5-C/D 的学习部分；若静态规则已近似最优，明确停止在该任务继续扩大神经模型。

继续沿用项目现有环境、正确性与日志约定；暂不新增 SHA-256 计算或单元测试，除非用户之后调整要求。

## 5. 后续架构研究的正确落点

若 M5 支持跨阶段前瞻比局部贪心/静态规则更有价值，下一步研究一种「结构化跨层级价值模型 + 可回溯搜索状态」：用 MLIR 执行合法变换、模型预测候选的后续潜力、实际硬件运行提供稀缺反馈、搜索器保留已验证的分支与测量经验。

它能否进一步需要持续神经表示、Cross-Attention、硬件资源 Token 等专门设计，需要由同预算消融回答。**最终论文贡献必须落到更好的生成代码或更少的调优成本，而不只是模型更复杂。**
