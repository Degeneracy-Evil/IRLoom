# Phase 0 审查与下一轮研究实验（2026-10-18）

审查基线：`main` 的 M0–M3 实现，最新提交 `bb999063`；参考 `experiments/reports/phase0-initial.md` 与代码 `irloom/compiler.py`、`irloom/measurement.py`、`benchmarks/workloads.py`、`benchmarks/runner.c`。以下为**源码和已提交报告审查**，未在该机器上重新运行基准，也未读取未提交的原始完整 IR、机器码和日志。

## 1. 评审结论

**Phase 0 工程目标已经基本完成。** 三类程序、每类两个尺寸、四种合法候选，两批均 24/24 通过正确性校验，共 720 次 batch-derived ms/kernel 计时样本。编译事件、六个 IR 边界、单核亲和性、热缓存测量、交错顺序、失败处理、独立 C 参考和原始样本记录的设计基本合理。未训练模型也符合原始目标。

**科学结论目前只达到“合法变换在本机产生稳定的程序/Shape 相关性能差异”。** 例如两轮 matmul 的 tile16 加速约 4.5–5.1×，stencil 的 tile16 却只达到 default 的约 0.19–0.21×。这是研究动力，不是新神经架构收益。两轮中的 720 个计时样本来自 24 个候选条件，**不能视为 720 个独立程序或训练样本**。

### 关键局限（按研究优先级）

1. **尚无真正的多阶段可选决策。** 当前 `compiler.py` 先统一执行 `--convert-linalg-to-affine-loops`，然后全部候选只在 affine 层执行一种 Tiling/Unroll。各候选的高层 IR 相同，既没有高层优化选项与后续低层选择的组合，也没有低层反馈回到高层的回溯。因此 Phase 0 暂不能检验持续跨层级状态的必要性。
2. **缺少强编译器基线。** `default` 是“无额外 affine 变换 + 相同后端 Clang -O3”，并不等价于成熟框架的自动调优最优结果，也不能把对它的加速直接声称超越最先进编译器。
3. **实现层面还缺少定性归因。** 完整 IR/反汇编仅在本机，报告未直接包含代表性候选的机器码差异；无法区分向量化、指令条数、访存模式、执行端口、缓存、寄存器等何者主导性能。不要把 Attention 归因建立在目前这些结果上。
4. **范围较窄。** 三个程序模板、每类两个静态 Shape、单核 x86、同一输入缓冲区重复调用，主要是热缓存小规模计算。模型泛化、真实内存层次和 ARM/RISC-V/Ascend 的适配均未验证。
5. **计时统计还不是强独立重复。** 15 个批量计时/候选在固定机器条件下稳定；两次连续运行结果一致，这是好迹象，但同主机共享负载、频率和跨批次依赖仍可能存在。bootstrap 区间应仅视为探索性区间。 

现有不计算 SHA-256、暂不写单元测试的实施约束保持不变；本轮不因这些事项重做 Phase 0。已有直接字节和反汇编比较足以支撑初期“同轮重复候选”检查，但不能用于跨机器产物完整性证明。

## 2. 下一步：M4 跨阶段决策交互实验

**目标：建立至少两个真实不同的优化决策点，并测量它们是否出现显著的性能交互。** 优先沿现有 MLIR→LLVM→CPU 工具链推进，不需要安装模型、重构编译框架或引入厂商硬件依赖。

1. **设计两个受控决策点。** 在 `linalg` 或其他较高层（A）加入一个合法且确实改变变换结果的优化选择；在较低层如 `affine`（B）保留 Tiling/Unroll 或另一种可控选择。须从当前 MLIR 18 工具链已支持的 Transform/Pass 中挑选组合，逐项确认合法且编译可执行。若现有基准难以容纳高层变换，可增添“matmul + elementwise”或可融合链式算子等**一个**示例，而不是一次扩几十种程序。Stencil 当前以 affine 起始，不应假装具有 linalg 高层语义。
2. **用小型因子设计而非暴力搜索。** 每个选定 Case 在至少 `2 个高层选择 × 2–3 个低层选择` 下测量，包含保留默认路径的对照；固定 Shape、精度、后端和测量流程。先选择一到两个能跑通跨阶段变换的程序，每个程序至少两个 Shape。失败和重复目标机器码的候选继续记录。
3. **检验真实的跨阶段交互。** 不只比较最优速度，还应画/报告“低层动作 B 的收益是否依赖先前高层决策 A”。例如使用对数延迟的交互差：
   `D = [log T(A1,B1)-log T(A1,B0)]-[log T(A0,B1)-log T(A0,B0)]`。
   比较独立重复批次与噪声；若某个低层动作在不同高层选择下出现收益符号反转，则特别值得深入分析。所有结论只针对实际受控候选。
4. **验证跨层级来源关系。** 至少挑两个代表性差异明显的候选，保留紧凑的高层/中层 IR diff、优化命令和函数级反汇编差异作为可审阅的样例。仅提交必要的文本摘录或生成说明，不上传所有日志或二进制。这一步不要求细粒度 Operation-level N:M 追踪。
5. **添加更强的现实对照。** 保留 Phase 0 的 `default`，同时明确记录一个有根据的常规优化 Pipeline 或等价 C/C++ `-O3 -march=native` 实现作为**参考**；严格区分参考实现可能不同的算法、布局和浮点语义。不要把参考速度与受控因素实验混在一起归因。
6. **覆盖至少一种跨缓存规模。** 在现有小尺寸上继续做对照，再添加 1–2 个使工作集跨 L1/L2 或更大缓存层级的 Shape。新增测量模式必须描述数据复用、输出重置与 Cache 状态，不能把 warm-cache 结果外推为带宽优化。

### M4 完成标准

能真实执行“高层 A × 低层 B”的合法编译组合，输出正确性、IR 快照、目标代码、两次独立批次性能与交互分析。报告明确指出观察到/未观察到跨层级决策交互，以及是否能仅用当前阶段 IR 和静态启发式解释；不给模型架构提前背书。

## 3. 进入模型研究之前的判定门槛

只有确认至少一种跨阶段交互或状态依赖确实值得利用，才开展公平的 B0/B1/B2 对照：

- B0：当前 IR + 目标机器信息 + 当前候选动作；
- B1：B0 + 高层原始语义/IR；
- B2：B1 + 变换历史（含此前真实决策）。

决策输入必须只包含那个时刻已知的信息，禁止把未来 LLVM IR、候选真实延迟和未来反汇编泄漏进模型。**模型性能收益最终应以相同测量次数和总体优化成本下选择更快代码为准，而不只是预测误差。** 使用足够多的独立程序及家族分组验证后，才能讨论持续状态与跨层级 Attention 相比直接编码完整历史是否具有额外价值。

若 M4 没有检测到有意义的交互，先复核变换空间与归因，而不是强行进入神经模型阶段。后续最有价值的论文问题仍是跨抽象层级协同决策与硬件性能反馈是否能带来**可复现的最终代码性能提升**。
