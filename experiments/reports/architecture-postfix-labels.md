## 实际范围与版本

从原 dataset 和 C2 影响清单生成固定执行计划，保留 Puzzle 的 36 条、DES 的 35 条记录及两个根默认。每条动作在新快照中按函数/结构路径、kind 和 parameters 定位，核对当前注册候选与原候选顺序、完整三阶段动作和 all-advance-v1 后缀。没有让模型重选路径，没有按新耗时筛选候选。

两个根默认各与原 S0 candidate 0 重合，因此 73 个规定记录/参照槽位映射到 **71 个实际编译终端**；其余重复产物也保留完整轨迹后再去重计时。本轮重建全部终端，没有借用旧二进制或直接沿用 C1 的 13 个可执行文件。71 条中恰好 13 条完整 ELF 改变（Puzzle 7、DES 6），其余 58 条与原 ELF 相同，但同组时间仍全部刷新。

恢复入口专用 Session 明确传入新 revision，分叉保留实际类型。每次命令执行前核对实际 bridge 与完整 manifest，observe/apply argv 必须指向 `benchmark-data/architecture/compilers/cleanup-positional-v1/bin/irloom-polygeist-bridge`；全部 79 个实际 session 的 manifest 及命令记录再次审计。历史入口默认 legacy 没有全局切换。本轮没有后续模型 raw/guarded 调用，也不声称这些旧入口已迁移。

复用 C1 的同版本构建：LLVM `26eb4285b56edd8c897642078d91f16ff0fd3472`、Polygeist `77c04bb2a7a2406ca9480bcc9e729b07d2c8d077`；按 operand 位置接续 cleanup carry。构建记录核对补丁正文与旧 archive 成员未提取的证据；未下载、重建整套 LLVM 或覆盖旧 SDK。编译继续使用原 O3、`-march=native`、`-ffp-contract=off`，输入、ABI 和阈值不变。

## 正确性、测量与实际成本

Puzzle 使用原无参数完整程序/完整输出，DES 使用原参数 `1`。每个终端在计时前与独立原 C 的 Clang O3 oracle 比较完整 stdout，全部通过；两个根默认同样检查。所有编译结束后，按程序把根默认、各前缀 advance 和全部原候选放进同一批，按 **完整可执行文件字节** 去重。每个代表产物计时六次，seed=71，三次随机顺序各接其反向，每次计时输出都与 oracle 比较。

原生进程按现有 Session 协议固定 CPU 0，无并行训练或其它项目编译。硬件/OS、240 CPU 的可用亲和范围、cache、编译器版本、flags 与前端版本保存在每个 session 的 `environment.json`、`manifest.json` 和命令日志；机器摘要保留具体 CPU 信息。采集开始 loadavg 约 Puzzle `[0.558,0.705,0.856]`、DES `[0.733,0.735,0.862]`。频率和外部服务负载未完全控制。新根默认中位数分别为 55.782794 ms、13.462655 ms；跨日期绝对耗时只作背景。
