# SQLite PGO 训练覆盖 A/B

固定官方 SQLite 3.50.4、Clang/LLD 18.1.3、native ThinLTO，按 [冻结协议](../../docs/REAL_AB_PROTOCOL.md) 执行。干净提交 `1024fd6`，日志 `logs/benchmarks/20261019T182016964969Z`，两批各十轮，共 80 个正式进程样本及 8 次丢弃预热，全部通过。完整逐轮数据、环境、源版本/许可证、最终 IR/汇编定位、训练/编译成本见同名 JSON。旧 R1–R3 及 Zstd 正式数据未覆盖。

## 训练与新评测隔离

P0 使用原官方 speedtest1 `--memdb --size 40 --testset orm,cte` 完整工作单位，P1 使用预冻结种子 42001 的显式二级索引点查询。均至少 60 进程 CPU 秒，采用 RUSAGE_CHILDREN 的 user+system 实测，末次完整单位差异限 1.2 秒。

| 组 | 完整执行次数 | 训练 CPU s | 训练及合并墙钟 s |
| --- | ---: | ---: | ---: |
| P0 | 83 | 60.201922 | 60.495 |
| P1 | 1 | 60.003343 | 60.062 |

两组相同官方核心编译配方/功能宏与相同 C++17 API 驱动，PGO 仅应用于核心，避免 speedtest1 main 与自定义 main 的函数体 profile 混用。生成/应用阶段均保留完整命令；核心启用 profile 不匹配为错误，构建成功。两份训练 profile、use 产物及 evaluation-only 计数分别隔离。正式运行所有四构建及两 profile 缓存命中。

测量前已冻结：N=100003，point 种子 52001 / 2000000 次查询，range 种子 62003 / 200000 次查询（每次 32 键）。输入未用于任一训练；值偏移和随机序列也与训练不同。逐条核对独立整数公式、范围 count=32，检查数据库 integrity、实际索引计划、版本及 SOURCE_ID。value_sum 是语义结果总和，没有计算产物 hash。旧 main 不作为新评测。

## 源码 → 最终代码 → 覆盖

目标位于同一 amalgamation TU。四处调用在两组最终核心 IR 中均真实存在，!DILocation 与下表行号对应，所选最终符号及汇编另存。训练覆盖是 llvm-cov 源语句 region 计数，不能把整条函数调用边累计数分配到一个位置。

## 解释与下一步

在这两种新索引负载上，P1完整进程配对中位速度比分别为 point +5.358%/+4.358%、range +1.879%/+2.133%；point 两批各10/10轮更快，range 为9/10及10/10。最终text由1327935降到1202003字节（减少约9.5%）；VdbeExec符号47312→43526字节，BtreeIndexMoveto符号1286→1666字节。普通PGO已能利用训练覆盖变化获得当前负载收益，目标边仍未内联，不能将收益归因于该调用动作，也没有据此提出神经模型需求。

第二批绝对耗时出现明显阶段漂移：point总体比第一批慢，range前半批也较慢，个别配对全进程差异达到约20%–31%。原始数据全部保留，不删除离群点；range第二批两组median之比约+8.7%，而同轮配对中位数仅+2.1%，因此不能用前者代替本报告的配对结论。两批主要方向相同，但系统干扰与小样本使泛化和因果精度仍有限，未声称统计显著。

本实验只改变传统 PGO 的训练分布。新评测与训练同属索引查询家族，point 是不同输入的近分布评测，range 也是索引查询，不能冒充广泛生产泛化；未重测 ORM/CTE 或旧 main，因此无法排除其退化。即使新输入收益稳定，也应先归为训练数据设计及常规 PGO 可利用的效果，不能据此证明新的神经编译架构必要性。

CPU0 单核亲和、轮次交错与第二批反转顺序；没有锁频、预留 SMT sibling 或控制邻核/缓存。正确性检查本身在计时内，适用于当前可复现查询驱动，不能外推无核查服务端绝对 QPS。profile 插桩训练负担也已计入，所有费用按真实子进程保存。本轮不扩大候选、不开发模型。下一步若继续，应先冻结更广的训练/评测家族及成本目标，再判断传统 PGO 剩余空间。
