# M4 结果解读与下一步

**本轮观察到可重复的跨阶段路径交互，但尚未证明跨层级历史表示有额外价值。** 运行环境为 Ubuntu 24.04、Intel Xeon 6986P-C、MLIR / LLVM / Clang 18.1.3，固定 CPU 0、单线程。完整统计见 [m4-interaction.md](m4-interaction.md)，原始计时及元数据见 [m4-interaction.json](m4-interaction.json)，代表性源码/IR/函数代码见 [m4-lineage.md](m4-lineage.md)。

## 已完成的实验

从干净提交 `97138e4` 运行 `bash scripts/phase0.sh m4`：两个 linalg 顺序 × 三个 affine 动作 × 三个 Shape，另加每个 Shape 的 C++ 常规参考。两轮独立重编译、分别以 order_seed=1/17 测量，均 21/21 正确，共 630 个 batch-derived ms/kernel 样本，其中 540 个属于因子实验、90 个属于 C++ 参考。它们来自 21 个候选条件，不是 630 个独立程序。

单入口总墙钟 91.66 s；两个 collect 分别 45.12 / 45.64 s，编译子进程各约 4.40 s；额外原默认路径等价检查编译约 0.60 s，计入总流程。完整成本见本机 `logs/m4-20261018T101246123107Z/workflow.json`。

所有 MLIR cell 保存七个边界及父路径；全部候选检查 seeds 0/1/7/19，每条 15 个计时样本。同一 Shape 的批量调用次数一致。两批相应候选的目标反汇编经直接字节比较完全相同；三个 Shape 的 A0 原默认路径等价检查也全部通过。没有计算 hash 或添加单元测试。

## 最明确的交互：tile16 的收益反转

下面的加速比以**同一 A 下的 none** 为基线，范围是两批各自的中位延迟比，不是置信区间。

| Shape (M,N,K) | ijk 下 tile16 加速比 | ikj 下 tile16 加速比 | 对数交互 D | 重复收益反转 |
| --- | ---: | ---: | ---: | --- |
| 32,32,32 | 1.014–1.038× | 约 1.301× | −0.249 至 −0.227 | 无；两边均改善，小尺寸 ijk 收益较小 |
| 127,65,93 | 5.036–5.095× | 0.326–0.328× | 2.731–2.751 | 有 |
| 1024,256,256 | 9.893–10.184× | 0.247–0.248× | 3.692–3.716 | 有 |

中、大尺寸上，两批的 D 探索性区间同向排除零；两个 A 的低层 log-effect 区间也分别处于零两侧。这里可以报告“这个 tile16 动作的效果依赖此前的 linalg 顺序”。Unroll4 的差异也重复出现，但在 ijk 下，大尺寸约 0.995× 的微小回退不应作为主要科学发现。

这些是单家族、同主机连续两批的受控路径结果；没有多重比较校正，也没有排除系统性干扰。报告中的 bootstrap 描述本批采样，不能替代更多独立程序、时间窗口和硬件重复。

## C++ 参考改变了对基线收益的解释

大尺寸 ijk 默认耗时约 66.42–66.55 ms；ikj-none 为 5.65–5.71 ms，普通 C++ ikj 为 5.62–5.64 ms。相对弱默认路径的约 12× 改善，并不代表超越常规 C++ 编译结果。非整齐尺寸的 ijk-tile16 比本次 C++ 参考稍快，但该参考未经调优，不能据此声称优于 BLAS 或成熟编译框架。

32×32×32 上，ikj-none 约 0.0132–0.0133 ms，反而明显慢于 ijk 默认约 0.0020 ms。简单地把“最内层连续访问”当成通用最优规则不成立，必须保留 Shape、编译结果和真实计时。

## 可审阅的代码差异与归因边界

以 127,65,93 为例，完整 kernel 函数中可直接看到：

| 路径 | 当前 IR 中 B 的最内层访问 | packed 浮点乘加指令存在性 |
| --- | --- | --- |
| ijk / none | 内层沿 k，B[k,j] 为跨行步长 | 未出现 vmulps/vaddps，出现标量 vmulss/vaddss |
| ikj / none | 内层沿 j，B[k,j] 连续 | 出现 vmulps/vaddps |
| ikj / tile16 | 分块后的循环与访问 | 未出现 vmulps/vaddps，出现标量 vmulss/vaddss |

`m4-lineage.md` 保存 default→ikj-none、ikj-none→ikj-tile16 的高层/affine/transformed diff、实际命令及函数级代码摘录，包含首个浮点乘法附近的指令，而不只展示函数序言。可确认这些路径确实改变了向量/标量实现形态，且与实际延迟差异同时出现。

这还没有证明向量化是唯一或主要原因：未做关闭向量化的受控消融，未采集 cache miss、执行端口或寄存器压力。不能用静态指令出现次数替代动态性能。高层顺序和 tile 会同时影响后端优化、循环管理、代码布局及数据访问；本轮只归因到编译路径整体。

12 KiB / 102 KiB / 2.25 MiB 覆盖了本机 L1d 48 KiB 和每核 L2 2 MiB 两条容量边界。但三种 Shape 同时改变迭代次数、边界和访问步长，且复用同一缓冲区。因此，本轮不是隔离 cache 容量影响的因果实验，也不是冷缓存或带宽优化证据。

## 对历史状态假设的影响

低层 B 决策点的 affine IR 保留了 ijk/ikj 的完整循环顺序和下标差别。即使只看当前 IR，也能辨认 B 是沿连续 j 还是跨行 k 访问，以及 unroll 将作用于哪个轴。因此：

- 可以确认“较早的优化决定会改变较晚动作的收益”。
- 当前静态信息足以区分这些状态，但本轮没有证明一个简单规则能预测所有候选的准确排名。
- 不能确认“必须保存历史才能作出更好选择”；没有出现当前 IR 相同而额外历史被证明有用的比较。

下一步优先检验当前 IR 的透明基线，增加独立家族与跨时间重复，并选择小型受控消融解释后端差异。只有在公平预算、家族分组和无未来信息泄漏的比较中发现历史增量价值，才考虑持续状态或跨层级 Attention。本轮不启动模型研究，也不把观察到交互自动当成神经架构立项依据。
